## 关于控制台

下面是关于控制台本身的常见问题。

| 问题                                     | 答案                                                                               |
| :--------------------------------------- | :--------------------------------------------------------------------------------- |
| 页面右上角显示「交互设计原型」是什么意思 | 当前是演示模式，指标、应用、规则和连接状态都是示例数据，不会访问生产服务或配置中心 |
| 没有登录也能读文档吗                     | 能。文档中心是公开静态内容，未初始化、未登录或依赖不可用时仍然可读                 |
| 为什么登录页没有初始化的入口             | 初始化是一次性流程，完成后服务端关闭窗口，登录页不再提供重新初始化的入口           |
| 我能直接调接口绕过界面上的限制吗         | 不能。界面隐藏只是体验，服务端在每个请求上重新判定角色                             |
| 切换语言会丢失当前文章吗                 | 不会。文章有稳定标识，切换语言时保持同一篇                                         |

## 关于规则

下面是关于规则本身的常见问题。

| 问题                                 | 答案                                                                                                 |
| :----------------------------------- | :--------------------------------------------------------------------------------------------------- |
| 为什么我填了预热或集群流控，发布被拒 | 当前 Java、Go、Rust 的 profile 只支持流量控制的一秒 QPS 直接拒绝子集，其它能力会被明确拒绝而不是忽略 |
| 保存草稿会不会影响线上               | 不会。保存草稿只写 Console 数据库，不写配置中心                                                      |
| 发布了为什么线上没变化               | 发布只更新配置中心。实例要等下一次轮询才加载，最多大约一秒                                           |
| 回退之后版本号变小了嗎               | 没有。回退是一次新的发布，版本号继续往前���，只是内容变回历史那份                                    |
| 规则数组是空数组，是不是等于没有规则 | 是的，空数组明确表示这个位置存在且没有规则。它和「读不到」是两回事                                   |
| 能手工往配置中心里塞一整份规则吗     | 可以，但整个快照必须符合 profile 的字段子集，否则适配器会拒绝整份快照而不是部分生效                  |

## 关于接入

下面是关于接入服务时最常问的问题。

| 问题                               | 答案                                                                      |
| :--------------------------------- | :------------------------------------------------------------------------ |
| Java 和 Go 的配置项能互换吗        | 不能。Java 的 NACOS_SERVER_ADDR 含端口，Go 拆成主机和端口两个变量         |
| Java 的证书能直接给 Go 用吗        | 不能。Java 用 PKCS#12，Go 和 Rust 用 PEM，变量名也不同                    |
| Java 的规则 JSON 能直接给 Go 用吗  | 不能。Go 的阈值字段叫 threshold 而不是 count，窗口字段是 statIntervalInMs |
| 三个 demo 的 /rules 返回格式一样吗 | 不一样。Java 和 Go 返回纯文本键值行，Rust 返回 JSON                       |
| 私钥要交给控制台吗                 | 不要。私钥永远不发送给控制台或 Collector，只登记证书指纹                  |
| 能不能用 token 代替 mTLS           | 不能。mTLS 是 Reporter 身份的唯一来源                                     |

## 关于指标

下面是关于指标口径最常问的问题。

| 问题                               | 答案                                                                   |
| :--------------------------------- | :--------------------------------------------------------------------- |
| 曲线空着是不是说明没流量           | 不一定。空表示这段时间没有有效样本，也可能采集链路有问题。缺测不等于零 |
| RT p95 能用平均 RT 代替吗          | 不能。两者回答不同问题，而且没有直方图就不该画 p95                     |
| 能拿主机 CPU 曲线当进程的 CPU 吗   | 不能。采集范围不同，容器级又是第三个范围                               |
| 没有埋点会有业务 TPS 吗            | 没有。TPS 只来自显式业务埋点，不会由 QPS 推算                          |
| 请求拦截率的分母是 0 会显示什么    | 显示不可用，不会显示零，也不会推断出比例                               |
| 多实例的 p95 是各实例 p95 的平均吗 | 不是。先合并桶计数，再在合并后的直方图上取分位                         |

## 更多问答

下面这些是跨主题的常见问题。

1. 先确认看到的是哪种模式，再确认身份与权限：角色只有 `admin` 和 `view`，能改规则的只有 `admin`。
2. 确认这次动作的影响范围：保存草稿、固化版本、发布是三件不同的事，只有发布会把内容写进配置中心。
3. 确认证据链是否闭合：发布回执、加载观察、实际的拒绝响应，三样都要拿到。
4. 任何一层对不上，先停下来核对事实，不要靠重复操作试探。

| 问题                                 | 答案                                                                                                                                                                                                                  |
| :----------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 控制台现在是演示模式还是真实环境     | 页面右上角显示「交互设计原型」、或登录页提示「本地演示模式」时是演示模式：指标、应用、规则和连接状态都是模拟内容，不访问生产服务或配置中心。演示登录名是 `admin` 和 `viewer`，而角色 id 只有 `admin` 和 `view` 两个。 |
| 这些文档覆盖全部能力了吗             | 没有。文档只覆盖已冻结并可验证的部分。接口契约声明存在，不等于真实集成或端到端验收已经通过。文档没给统一定义的地方，以实际实现为准。                                                                                  |
| 规则内容能手工改吗                   | 能，但整份快照必须符合绑定 profile 的字段子集。适配器会拒绝整份快照，不部分生效，也不静默删掉不认识的字段再写回。                                                                                                     |
| 能一次改多条规则吗                   | 能。一个版本最多 1000 条规则记录，一次候选校验最多 32 条 issue。发布是整份替换，写下去的是这一版的全部内容。                                                                                                          |
| 发布是增量的吗                       | 不是。发布是整体替换，该位置内容被这一版完整覆盖。要保留旧规则，必须先把它们包含进新版本再发布。                                                                                                                      |
| 能直接改正在生效的规则吗             | 不能。生效中的内容在配置中心里，不在 Console 的草稿里。要改先建草稿、校验、固化成新版本，再发布。                                                                                                                     |
| 加载观察和发布回执哪个更权威         | 各答一个问题。发布回执说「写成了什么」，加载观察说「进程实际加载了什么」。要证明请求真被拦截，还得有实际的拒绝响应。                                                                                                  |
| 指标能预测容量吗                     | 不能。指标是事后观测，不是容量模型。阈值靠压测基线和 SLO 推出来，指标只用来验证调整后的效果。                                                                                                                         |
| 主机关联能自动推断吗                 | 不能。主机关联是显式登记的，不会从抓取标签推断。                                                                                                                                                                      |
| Console 能跨主机部署多个副本吗       | 当前契约不支持。`SENTINEL_CONSOLE_WORKERS` 是同一台主机上的 Uvicorn worker 进程数，默认 `1`；多 worker 只在共享同一套本地部署状态路径和同一个 SQL 数据库时受支持，NFS 和多主机副本不在覆盖范围内。                    |
| 加载观察里的成员清单能当完整性证明吗 | 不能。`membership_complete` 为 false 时成员清单是空的，要显示未知，不能当成「没有规则」。                                                                                                                             |
| 发布返回 202 能说明写成功了吗        | 不能。202 只表示服务端接受了这一个幂等操作。要看三阶段跑完后的阶段状态，以及回执是 `applied`、`pending`、`failed`、`unknown` 还是 `restart_required`。                                                                |
