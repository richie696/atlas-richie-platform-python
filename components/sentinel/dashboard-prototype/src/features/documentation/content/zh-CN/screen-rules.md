规则页是控制台里最复杂的一页。它同时承担三件事：**看现在配置了什么**、**确认运行时到底加载了什么**、**安全地改一次**。这页用两栏导航把它们分开：左边是四个主段，右边在「规则维护」下再展开四个步骤。

## 四个主段和四个步骤

| 主段         | 回答什么问题                       | 里面有哪些面板                                                                                               |
| :----------- | :--------------------------------- | :----------------------------------------------------------------------------------------------------------- |
| 规则目录     | 配置中心现在有哪些规则             | 配置中心规则目录、规则类型卡、搜索、未确认的配置来源                                                         |
| 实例生效状态 | 哪些实例真的加载了、有没有加载成功 | 配置源读取状态、实例规则加载状态、历史进程观察                                                               |
| 绑定管理     | 应用和配置中心规则集是什么关系     | 规则集绑定目录、登记规则集绑定                                                                               |
| 规则维护     | 我要改的那条规则现在长什么样       | 规则集编辑器、已保存草稿、发布目标、不可变规则版本、发布进度与实例回执、活动版本与恢复计划、最近一次后台操作 |

「规则维护」下的四个步骤按顺序用：**编辑规则 → 已保存草稿 → 版本与发布 → 恢复计划**。

> **提示** 编辑、版本发布和恢复计划都需要先选中一个规则集绑定。没选绑定时页面会直接告诉你「先选择一个规则集」，而不是显示一个空的编辑框。

## 规则目录：先确认你读到的是全的

规则目录直接从已登记的 Nacos / Consul 读取规则快照。目录顶部有一行覆盖说明，它决定下面的清单能不能当全集使用：

| 覆盖说明                    | 含义                 | 后果                                         |
| :-------------------------- | :------------------- | :------------------------------------------- |
| 已完整读取 X / Y 个绑定     | 全部绑定都读到了     | 清单可信                                     |
| 当前仅确认读取 X / Y 个绑定 | 有绑定没读到或已过期 | 清单**不完整**，不能据此认为「没有其它规则」 |

目录里的每一行给出资源名、阈值摘要、配置来源、配置读取状态（当前快照 / 过期快照）和实例使用情况。过期快照保留上次成功读取的内容，但会明确标出来。

### 规则类型卡：五类规则在这里选

目录上方有五张卡：流量控制、熔断降级、系统保护、访问控制、热点参数。点「查看此类规则」会把下方目录筛选成该类型。卡片是**筛选器**，不是创建入口。

### 规则详情：四个分区

点开某条规则会展开详情分区：

| 分区       | 给出什么                                       | 不能从中得出什么                                   |
| :--------- | :--------------------------------------------- | :------------------------------------------------- |
| 配置详情   | 该规则在配置中心里的字段值与快照校验和         | 快照新鲜度之外的内容                               |
| 已加载实例 | 哪些实例确认加载、哪些确认未包含、哪些尚未确认 | 未列出的实例是否加载                               |
| 请求效果   | 逐规则的命中与阻断                             | 没有逐规则读模型时，不能把资源级流量归因到这条规则 |
| 发布历史   | 这个 binding 的发布记录                        | 不能归因到单条规则                                 |

> **提示** 「实例使用情况」里的三个数字要分开读：确认加载、确认未包含、**尚未确认**。第三类不是「没加载」，是证据不足。

## 实例生效状态：两组读数

| 面板             | 读的是什么                         | 关键区分                                   |
| :--------------- | :--------------------------------- | :----------------------------------------- |
| 配置源读取状态   | 按绑定读 Nacos / Consul 的实际结果 | **目标缺失**与**确认空规则**是两个不同状态 |
| 实例规则加载状态 | 已登记运行时实例的加载回执         | 只依据 Collector 持久化的回执              |

区分这两个状态很重要：绑定指向的目标不存在，说明配置写错了地方；目标存在但规则为空，说明规则确实被清空了。前者要改绑定，后者要改规则。

> **提示** 目录完整性不足时，页面会显示「观察结果不完整，不能推断规则未使用或配置为空」。这句话是字面意思，别绕过它下结论。

## 绑定管理：规则从哪里来

绑定目录列出应用与配置中心规则集之间的绑定。登记一个新绑定要写明：环境、应用、配置中心类型、寻址位置（命名空间或数据中心）和规则集标识。

绑定的配置有七种状态：

| 状态           | 含义                           |
| :------------- | :----------------------------- |
| 当前含规则     | 绑定可用且目标里有规则         |
| 确认为空       | 绑定可用，但目标里确认没有规则 |
| 目标缺失       | 目标不存在                     |
| 内容无效       | 读到了内容但不符合约定         |
| profile 不支持 | 该 profile 覆盖不了这个绑定    |
| 来源不可用     | 读不到                         |
| 尚未读取       | 没读过                         |

## 规则维护：改一次要走完四步

改一条规则的完整路径：

1. **编辑规则**：在规则集编辑器里改字段，保存为草稿。保存草稿**不改变**运行中的规则。
2. **已保存草稿**：草稿可以继续编辑，也可以查看它对应的规则基线。
3. **版本与发布**：把草稿固化成不可变版本，再发布到配置中心。固化有 5 条前置条件，发布也有 5 条。
4. **恢复计划**：需要延迟生效或回退时，在这里管理计划。

| 动作       | 通道                                                                    | 前置条件不满足时                                   |
| :--------- | :---------------------------------------------------------------------- | :------------------------------------------------- |
| 校验       | `POST /api/v1/rulesets/{bindingId}/commands` 之外的 `validate` / `diff` | 返回具体路径的问题                                 |
| 固化成版本 | `freeze_version`                                                        | 422 `rule_freeze_not_ready`                        |
| 发布       | `publish`                                                               | 409 `conflict`（弹窗意图与当前事实逐字段比对未变） |

> **提示** **回滚不是独立命令**。回退是「以当前配置为基线再发一次发布」。所以回退也会留下版本和审计记录。

> **提示** 浏览器不执行调度。启用和恢复由后台执行，关掉浏览器不会取消。

## 规则页的时间范围为什么没反应

规则页顶部也有环境、应用和时间范围，但规则页的所有读取都是**时点读**——它读的是当前快照、当前目录、当前草稿、当前版本和当前回执。地址里的 `range` / `from` / `to` 在这一页只做透传，没有消费点。

> **提示** 想看「某段时间的规则变更历史」，要去规则详情里的发布历史，或去系统管理的操作审计。规则页本身不按时间窗筛规则。

## 改之前先确认这四件事

1. 绑定上标注的 profile 是什么，它支持哪几类规则。
2. 这一条规则的字段单位：秒还是毫秒，比例是 0 到 1 还是 0 到 100。
3. 当前草稿相对当前版本改了哪些字段——用 `diff` 看，不要凭记忆。
4. 发布前置条件是否都满足，尤其是「弹窗意图与当前事实逐字段比对未变」这一条：你在弹窗打开之后、确认之前，页面上如果已经变了，发布会被拒。
