## 规则与配置

下面这些词描述「规则存在哪里、长什么样、谁认它」。

| 术语     | 一句话解释                                                                                                                                                                                                 |
| :------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 规则类型 | 五类规则之一：流量控制、熔断降级、系统保护、来源访问控制、热点参数                                                                                                                                         |
| 规则绑定 | 把环境、应用、规则类型、配置位置和运行时 profile 关联起来的一条记录。规则工作台靠它定位配置                                                                                                                |
| 配置位置 | 规则在配置中心里的具体坐标。Nacos 用 namespace ID + group + Data ID；Consul 用 datacenter + 完整 KV key                                                                                                    |
| profile  | 一份「这个运行时认哪些字段、认哪些语义」的约定。sentinel-python-v1、sentinel-java-v1、sentinel-go-v1、sentinel-rust-v1 是规则 profile；node-exporter-v1 是主机指标采集 profile，两者不是一回事             |
| 原生数组 | 配置中心里就是一个 JSON 数组，每个元素一条规则。Sentinel Java 和 Go SDK 原生读这个格式                                                                                                                     |
| 托管信封 | Managed Rule Publication Envelope V1：Console 写入配置中心的规则发布封装，包含绑定、规则类型、profile、发布标识与原生规则载荷；不是 Reporter 上报信封。Runtime 必须显式启用 managed-envelope-v1 才能消费。 |
| 草稿     | 保存在 Console 数据库里的可编辑内容。保存草稿不会改配置中心                                                                                                                                                |
| 版本     | 冻结后的不可变快照。一经创建不能修改，要调整只能基于它新建草稿                                                                                                                                             |
| 发布     | 把某个版本整体写入配置中心，然后独立读回比对                                                                                                                                                               |
| 回执     | 运行时回报「某一次发布到达了我」的记录。托管发布才有                                                                                                                                                       |
| 加载观察 | 运行时主动上报「我现在生效的是这份快照」。原生规则靠它，加载观察与回执是两回事                                                                                                                             |

## 运行时与观测

下面这些词描述「业务进程里发生了什么、以及它上报了什么」。

| 术语            | 一句话解释                                                                        |
| :-------------- | :-------------------------------------------------------------------------------- |
| Reporter        | 跑在业务进程里、主动把指标与加载状态上报给 Collector 的组件                       |
| enrollment      | 运维侧把一个 Reporter 的证书指纹登记到 Console 的动作。证书私钥永远不交给 Console |
| Collector       | 接收 mTLS 上报、持久化并对外提供查询的服务                                        |
| mTLS            | 双向 TLS。客户端和服务端互相验证书，是 Reporter 身份的唯一来源                    |
| 成员指纹        | 一条规则的规范化指纹。清单完整且互相匹配，才能证明某条规则确实被加载了            |
| last-known-good | 最近一次成功读取的内容。读取失败时保留它，但它只代表上一次，不代表这一次          |
| 原子事件        | 进程启动标识。进程重启后标识变化，旧事件不能代表当前进程                          |
| scope           | 指标的采集范围：进程级、宿主机级、容器级。三者不能互换                            |

## 控制台与权限

下面这些词描述「控制台自己怎么管理权限和数据」。

| 术语            | 一句话解释                                                                               |
| :-------------- | :--------------------------------------------------------------------------------------- |
| 管理员（admin） | 同时持有查看指标与写规则两项能力                                                         |
| 查看者（view）  | 只持有查看指标能力，能看图表和只读内容，不能改任何东西                                   |
| metrics:view    | 查看指标、趋势图和实例指标详情的能力                                                     |
| rules:write     | 新建、修改、停用、发布、回滚规则的能力                                                   |
| setup-window    | 初始化窗口。部署方显式开启后，浏览器端的一次性初始化向导才可用；初始化完成后服务端关闭它 |
| operator code   | 远程初始化时的一次性授权码。由部署方保管，只在初始化窗口开启期间有效                     |
| 幂等键          | 同一个请求标识。重复提交同一个键不会产生第二次写入                                       |
| 回读            | 写完之后独立再读一次并比对。用来区分「写成功了」和「以为写成功了」                       |

## 指标与时间

下面这些词描述「图上的数字到底怎么算出来的」。

| 术语         | 一句话解释                                                                 |
| :----------- | :------------------------------------------------------------------------- |
| HTTP QPS     | 已完成响应的 HTTP 请求数除以经过秒数。包含 4xx 和 5xx                      |
| 资源调用速率 | Sentinel 入口计数（放行 + 拦截）除以经过秒数。一次 HTTP 可能进入多个资源   |
| 业务 TPS     | 应用显式埋点的已完成业务事务除以经过秒数。没埋点就没有这个数               |
| RT p95       | 同一请求边界上 95 分位响应时间。由直方图算出，取桶上界，不做插值           |
| 请求拦截率   | 被拦截数除以尝试数。跨实例要先分别求和再相除                               |
| 缺测         | 这段时间没有有效样本。它不等于零流量                                       |
| 采样覆盖     | 已上报的对象数与预期对象数之比。预期未知时显示「未知」，不用当前页条数冒充 |
| UTC 半开区间 | 控制台的查询窗口是 [from, to)，不含 to 那一刻                              |

> **提示** 指标名里的词都是协议值，它们在各语言各产品里保持一致；具体产品的界面文案可以翻译，协议值不翻译。

## 常见缩写

下面这些缩写会在命令、配置项、协议值和界面文案里反复出现。先看最常出现在配置与接口里的几个字面形态。它们是协议值，在命令、配置文件和接口返回里都按这个写法出现，不会被翻译。

表格再逐个说明每个缩写在本手册语境下的具体所指。第三列不是词典释义，而是这份系统里它实际承担的东西。

```bash

metrics:view
rules:write
admin
view
http_qps
resource_entry_rate
rt_p95
blocked_ratio
tps
cpu_ratio
memory_ratio
memory_bytes
```

| 缩写        | 全称                              | 在本手册里指什么                                                                                                                                                                   |
| :---------- | :-------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| QPS         | Queries Per Second                | 每秒完成的请求数。指标协议值是 http_qps，分子是已完成的 HTTP 响应增量，包含 4xx 与 5xx。                                                                                           |
| RT          | Response Time                     | 一次请求从进入到结束的耗时。指标协议值是 rt_p95，取的是同一请求边界上的 95 分位响应时间。                                                                                          |
| TPS         | Transactions Per Second           | 每秒完成的业务事务数，来自应用显式埋点。没有埋点就没有这个数，接口调用数不能替代它。                                                                                               |
| p95         | 95th percentile                   | 样本排序后处于 95% 位置的值。本手册的 p95 由合并直方图按 nearest-rank 算出，取桶上界，不做插值。                                                                                   |
| mTLS        | mutual TLS                        | 双向 TLS。客户端与服务端互相验证证书，Reporter 的身份只由证书指纹确定，私钥不离开业务进程。                                                                                        |
| CA          | Certificate Authority             | 签发并担保证书的信任根。控制台用 PEM CA bundle 配置来源与数据库的信任根。                                                                                                          |
| CAS         | Compare-And-Swap                  | 带前置条件的原子写。Consul 用真正的 CAS 写规则，Nacos 没有等价的原子条件写。                                                                                                       |
| SDK         | Software Development Kit          | 业务进程里嵌入的 Sentinel 客户端库，负责读规则、埋点与上报。                                                                                                                       |
| CLI         | Command Line Interface            | 控制台随包提供的命令行入口，例如 sentinel-console serve 和 sentinel-console setup-window status。                                                                                  |
| API         | Application Programming Interface | 应用程序接口的统称。本系统中浏览器调用 Console API；Reporter 通过独立上报协议连接 Collector，二者不是同一个接口。                                                                  |
| JSON        | JavaScript Object Notation        | 配置中心里规则的存储格式。原生数组是一层 JSON 数组，托管信封是带外层结构的 JSON 对象。                                                                                             |
| UTC         | Coordinated Universal Time        | 控制台所有时间戳与查询窗口使用的时区。查询窗口是半开区间 [from, to)，不含 to 那一刻。                                                                                              |
| profile     | 英文术语直用，无固定全称          | 一份「这个运行时认哪些字段、认哪些语义」的约定。规则 profile 有 sentinel-python-v1、sentinel-java-v1、sentinel-go-v1、sentinel-rust-v1；主机指标采集 profile 有 node-exporter-v1。 |
| fingerprint | 英文术语直用，无固定全称          | 内容的摘要标识。证书指纹用来登记 Reporter，规则成员指纹用来证明某条规则确实被加载。                                                                                                |
| Reporter    | 英文术语直用，无固定全称          | 跑在业务进程里、主动把指标与加载状态上报给 Collector 的组件。                                                                                                                      |
| Collector   | 英文术语直用，无固定全称          | 接收 mTLS 上报、持久化并对外提供查询的服务，是运行时上报内容的权威。                                                                                                               |
