## ホスト指標とプロセス指標は別のもの

ホスト監視は Prometheus 互換バックエンドを使い、profile は node-exporter-v1 です。ルール profile とは全く別のプロトコル層なので、同じ対応表の中で理解しないでください。

| ホスト指標             | 意味                                 | 範囲   |
| :--------------------- | :----------------------------------- | :----- |
| host_cpu_busy_ratio    | ホストの CPU 稼働率。0 から 1 の比率 | ホスト |
| host_memory_used_bytes | 使用済みメモリバイト数               | ホスト |
| host_memory_used_ratio | 使用済みメモリ比率。0 から 1 の比率  | ホスト |
| host_load_1m           | Linux の 1 分間平均ロード            | ホスト |

> **注記** node-exporter-v1 はコンテナ指標（cAdvisor の領域）、Windows 指標、ディスクとネットワークの健全性をカバーしません。プロセス指標もカバーしません。host_load_1m は CPU コア数を超えることがあり、パーセントでも正規化済みの飽和度でもありません。

## コレクターを配置する

まず収集自体を動かしてからコンソールを設定します。逆順では時間がかかります。コンソールに曲線が出ないとき、採取できなかったのか設定が合っていないのかを区別できないためです。

1. 対象のマシンに node_exporter を配置します。
2. Prometheus にスクレイプ対象を設定します。
3. Prometheus 自身の画面で対象が up であり、必要な指標が存在することを確認します。
4. コンテナで配置する場合はホストのリソースを正しくマウントします。そうしないと採取されるのはコンテナや仮想マシン自身の指標で、物理ホストのものではありません。

## コンソールに監視ソースを登録する

登録するのは Prometheus の照会バックエンドのアドレスです。報告先でも、コレクター自身の /metrics アドレスでもありません。

1. 配置側で監視対象からのアクセスを許可し、監視対象を登録します。
2. システム管理の「接続と収集」タブで監視ソースを登録します。Prometheus の照会アドレス、認証方式、環境、profile を入力します。
3. 接続をテストし、プローブ結果が使えることを確認します。
4. サンプルが読み取れることを確認します。接続に成功しても、その時間範囲にサンプルがあるとは限りません。

> **注記** Actuator のエンドポイントを単体で公開しても、本システムのアプリケーション指標が自動的に揃うわけではありません。サポートされている照会マッピングを使うか、Reporter を接続してください。

## ホストとインスタンスの紐付けを保守する

ホストと稼働インスタンスの対応関係は管理者が明示的に保守します。ホスト名や Prometheus のラベルから自動推論されることはありません。

1. 「アプリケーションとインスタンス」ページの「ホスト一覧」タブを開きます。
2. ホストを 1 台選びます。
3. 「稼働インスタンスの関連付け」欄で関連を追加し、アプリケーション識別子とインスタンス識別子を入力します。
4. 関連を確認すると、ホストのリソース曲線が対応するアプリケーションに割り当てられます。

> **注記** 未関連付けのホストも一覧には表示されます。「すべてのアプリケーション」に切り替えれば、未関連付けのホストを確認できます。関連付けが確定しない場合は、関連一覧を更新してからやり直してください。連続して送信しないでください。

## 接続はできるのに曲線が出ない

次の順番で確認すれば，ほとんどのケースに対応できます。

1. スクレイプ対象が up で、Prometheus でサンプルを照会できることを確認します。
2. ラベルが一致することを確認します。ホスト名のラベル、時刻のラベル、インスタンス識別子がそろっているか。
3. profile に必要な 4 つの指標がすべて存在することを確認します。
4. 選択した時間範囲にデータがあり、採取したばかりの未蓄積ではないことを確認します。
5. データの鮮度が切れていないことを確認します。
6. 最後に、このインスタンスとホストの間に明示的な関連付けがあることを確認します。

> **注記** IP が同じという理由だけで、ホストがインスタンスに属すると判断しないでください。関連付けは明示的に保守される事実であり、推論されたものではありません。

## ホスト指標とプロセス指標の確認場所

プロセス指標とホスト指標はまったく異なる経路から取得され、集計範囲も異なります。以下の表で指標ごとの範囲と確認場所を示します。

| 指標                   | 範囲           | 確認場所                                         | 取得元                                                    |
| :--------------------- | :------------- | :----------------------------------------------- | :-------------------------------------------------------- |
| cpu_ratio              | プロセス scope | リアルタイム監視、アプリケーションとインスタンス | Reporter が報告したプロセス CPU                           |
| memory_ratio           | プロセス scope | リアルタイム監視、アプリケーションとインスタンス | Reporter が報告したプロセスの使用済みバイトと検証済み上限 |
| memory_bytes           | プロセス scope | リアルタイム監視、アプリケーションとインスタンス | Reporter が報告したプロセスの RSS バイト数                |
| host_cpu_busy_ratio    | ホスト scope   | ホスト一覧、リアルタイム監視のホストリソース推移 | node-exporter-v1 を Prometheus で照会                     |
| host_memory_used_bytes | ホスト scope   | ホスト一覧、リアルタイム監視のホストリソース推移 | node-exporter-v1 を Prometheus で照会                     |
| host_memory_used_ratio | ホスト scope   | ホスト一覧、リアルタイム監視のホストリソース推移 | node-exporter-v1 を Prometheus で照会                     |
| host_load_1m           | ホスト scope   | ホスト一覧、リアルタイム監視のホストリソース推移 | node-exporter-v1 を Prometheus で照会                     |

> **注記** 両者は別に集計され、互いに補い合いません。プロセス指標が未接続なら「未接続」、ホスト指標がその時間範囲にサンプルがなければ「サンプルなし」と表示されます。片側がもう片側の数値で埋めることはありません。host_load_1m は CPU コア数を超えることがあり、パーセントでもなく、対応する集約基準もありません。
