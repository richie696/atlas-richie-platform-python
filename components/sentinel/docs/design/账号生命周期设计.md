# 账号维护补全：本人改密、管理员重置与删除

## 解决的业务场景

**场景**：三种常见却处理不好的账号问题——本人忘记密码无法登录；
某个账号的凭据外泄需要管理员强制换密；离职或废弃账号需要回收，
但不能把用户名放出去被新账号冒用，也不能删到最后一个管理员导致整个控制台无人可管。

**本文给出的设计**：本人改密沿用既有 `/api/v1/auth/password`，
管理员重置与删除扩展既有账号命令通道，沿用同一套 Origin、CSRF、revision 条件更新、
幂等键与审计机制；重置与删除都先在服务端同一事务内复核目标状态、内置标记、
自身标记与最后管理员约束。

**解决后得到什么**：账号可以被安全回收而不产生"无人可管"的死角；
每次重置、删除都有审计留痕，且成功后目标账号的会话被立即撤销。

**边界**：不新建第二个身份存储、密码摘要格式或业务事件总线；
UI 的禁用态只是说明，真正的权限边界在服务端。

## 用例与边界

头像菜单向所有已登录用户固定提供「修改密码」；管理员另有「账户维护」，不再二选一。本人改密沿用 `/api/v1/auth/password`：旧密码、新密码与 UI 确认，由服务端变更并撤销全部会话。

在现有账号命令通道 `/api/v1/accounts/commands` 增量增加 `reset_password` 与 `delete`，沿用明确 Origin、CSRF、当前 admin 会话、账号 revision CAS、幂等 HMAC、原子事务和审计；不创建第二个身份存储、密码摘要格式或业务事件总线。按已存在的命令与持久化 Adapter 扩展，无新增设计模式或第三方依赖。Console OpenAPI 从 0.18.0 增量发布为 0.19.0。

## 交互与保护

- 重置密码：账号行打开统一 DialogFrame；显示目标账号、单个新密码框及会话撤销说明。不需要对方旧密码，不增加确认密码。不读取或回显已保存密码；当前输入可切换明文以便复制，不进入 URL、查询缓存、持久化状态、审计或操作回执。提交时清空表单；未知结果只能读回原操作，不盲目重发。
- 生成密码（同日补充需求）：重置弹窗提供「生成密码」，Web Crypto 本地生成 24 位 URL-safe 随机字符（144-bit entropy，256/64 整除，无 modulo bias），自动填入并显示以便操作员复制；可隐藏、编辑或重复生成。生成不会提交请求。随机源不可用时明确提示手动输入，绝不退回 Math.random。选择固定 24 位符合当前 12–1024 码元策略且便于运维使用；不引入后端生成接口或额外依赖，以免凭证增加网络/日志暴露面。
- 管理员可以在账户维护中重置自己的密码，包括内置 admin；这用于忘记当前密码时的恢复。内置账号只能由本人执行密码重置，不能被其他管理员重置。成功后立即撤销目标账号全部会话，并要求重新登录。本人仍可从头像菜单使用旧密码修改；普通/已停用账号可以被管理员重置，但不会自动启用。
- 删除：再次显示目标账号并要求输入账号名确认；后台逻辑删除，保留审计、规则版本及外键引用，普通目录/详情不再显示，登录拒绝，全部会话撤销。原用户名继续保留，避免历史身份被新账号冒用。
- 内置账号、自身账号、最后一个有效管理员不能删除。内置账号不能停用或降级；自身密码重置允许，其他内置账号的密码重置拒绝。启停用沿用现有规则；删除账号不能被旧页面再启用、改角色或重置。
- 服务端对目标存在、未删除、revision、内置/自身/最后管理员在同一 guard 事务中复核；UI disabled 仅为说明，不是权限边界。
- 模态由 feature 私有组件承载，沿用 Astryx 和 DialogFrame；不覆盖表单控件全局样式。中/英/日文案与文档中心同时更新。

## 数据与协议

`console_account.deleted_at` 为 nullable UTC 时间，现有账号默认 NULL。删除设置 disabled、deleted_at、updated_at 并增加 revision；不物理删除账号。账户安全返回结构不新增密码或哈希字段；成功回执保持账号的安全快照，客户端以目录重读确认删除。新增业务拒绝 `self_operation`，不泄漏原始数据库异常。

新命令：`{kind:'reset_password', requestKey, accountId, revision, password}` 与 `{kind:'delete', requestKey, accountId, revision}`。密码字段 writeOnly，其他额外字段拒绝；重置与删除均返回原有 completed/rejected 最终回执。admin 可将 reset 命令的目标设为自身，服务端仍以当前 admin 会话、CSRF、revision CAS 和事务约束校验；回执确认后客户端清除本地身份并转到登录页。自身删除仍返回 `self_operation`。旧操作仍可按 actor 和 requestKey 读回。

## 定向验收矩阵

| 边界 | 必测结果 |
| --- | --- |
| 菜单 | admin/view 都有本人改密；admin 额外有账户维护 |
| 权限 | 无会话拒绝、view 拒绝、错误 CSRF 拒绝；事务内重新验证 admin |
| 重置 | 新密码能登录、旧密码失效、旧会话失效；停用状态不变；不回显/持久化明文 |
| 删除 | 从目录/详情消失、不能登录/复活；历史账号 FK、审计与幂等回执仍可读取 |
| 保护 | 内置、自身、最后一个管理员和 stale revision 拒绝且无副作用 |
| 幂等 | 相同键同内容只增加一次 revision/审计；同键不同密码冲突 |
| 迁移 | 已有 PG 数据不变，新增列及回执约束可升级；不重做 setup |
| UI | 统一弹窗、单密码框、删除确认、忙碌/失败/未知结果、三语、键盘焦点 |

只在已运行的专用 `sentinel_console` 库创建合成账号做定向真实接口验证；不修改用户 admin 密码，不删除原有账号，不启动额外容器。浏览器验证菜单与弹窗；密码设置/修改的真实断言由受控测试账号 API 完成，不替用户在浏览器修改真实凭证。
