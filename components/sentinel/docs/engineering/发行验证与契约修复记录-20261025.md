# 发行验证与契约修复记录（2026-10-25）

本轮只处理已报告的 wheel 隔离安装、Metrics V2 诊断、口令合同和文档索引问题。
保留同一工作区已有的文档迁移与其他改动；不执行发布，不启动容器，不重复产品 E2E。

## 选择、原因与替代方案

| 问题 | 采用方案与原因 | 未采用方案及原因 |
| --- | --- | --- |
| uv venv 没有 pip | 准备脚本创建临时 stdlib venv，工具生命周期由脚本管理；workspace 环境不需要安装 pip | 向开发环境永久安装 pip 会掩盖脚本的隐含前提，其他机器仍会失败 |
| 锁定包只有 sdist | `pip wheel --require-hashes --no-deps` 验证 runtime lock 哈希后，在准备阶段隔离构建 wheel；安装阶段只读本地产物 | `--only-binary=:all:` 会拒绝 7 个实际锁定的源码包；取消哈希校验或在安装验证时访问索引会削弱门禁 |
| 隔离安装名单过时 | 从 workspace 成员的 project name/version 和 uv build module-name 读取精确清单，逐包创建新环境，固定所有内部依赖版本，使用 `-I` 检查导入文件确实位于新环境 | 硬编码统一 platform version 不适用于有独立版本的 reporter/dashboard；扫描 dist 会混入旧包、漏掉新包 |
| 契约兼容投影补回旧值 | 缺字段、变体、参数、状态码直接失败；只按 operation、schema 路径、精确值剔除已批准差异；添加故意删除/变更的负向测试 | 通用忽略所有新增 enum/variant/semantic rule 会漏掉未批准变化；把旧值填回当前树会让删除也通过 |
| 新密码仍带 1024 正则 | 身份模块定义唯一 NewAccountPasswordSchema，从 32 上限构建 UTF-16 正则，覆盖创建、初始化、自改和重置 | 直接手改生成 OpenAPI 会在下一次生成时丢失；修改共享凭证上限会影响登录旧密码和配置中心认证 |
| Go/Python Metrics V2 诊断漂移 | 保留 Python 生产错误码枚举和 wire 字段，修正 Go 测试校验器，使同一共享夹具断言同一精确错误码；诊断清单放测试目录 | 修改冻结协议标识、重命名生产错误码，或新增跨语言生产 SDK 均超出修复所需；本轮不伪造协议 owner 签字 |
| 嵌套指标对象字段失败 | Python 原本会构造未登记的 `invalid_counter_fields` 等代码并抛 RuntimeError；改用已登记的 `invalid_counter` / `invalid_histogram` / `invalid_gauge`，维持拒绝且不新增 wire 枚举 | 新增 3 个生产错误码需要额外扩展冻结的诊断表；吞掉非法字段会破坏严格解码 |
| 历史 OpenAPI 归档缺失 | 检索可达 Git 历史并在协议索引明确标注原始快照缺口与恢复来源要求 | 从当前文件裁剪、改版本号无法证明历史原貌，不作为归档恢复 |

准备阶段上游 sdist 的 build-system 依赖遵循上游声明，未被 runtime lock 固定；因此本轮证明
runtime 来源哈希和离线安装隔离，不声称构建过程可逐字节复现。临时产物统一置于
`/tmp/atlas-release-check-yMaWCN`，未修改用户现有 Docker 服务。
