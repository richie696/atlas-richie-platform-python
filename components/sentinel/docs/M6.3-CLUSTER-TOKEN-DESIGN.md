## 1. 背景与动机

PLANNING §M6.3: 实现 `components/sentinel/sentinel-cluster/` 的分布式
`TokenService`, 让多个 SentinelEngine 能为同一 resource 申请共享额度
或并发 lease. 普通业务代码仍只调 Engine, 不直接调 Token Server.

**关键不变量** (PLANNING §M6.3 验收):
- `FAIL_CLOSED` 实际 grant 总量不得超出 Server 认定的配额
- `FAIL_OPEN` 不承诺不超发, 但每次放行都必须有可查询决策 + 指标
- `LOCAL_FALLBACK` 显式配置, 不伪装共享配额
- **禁止默认静默放行**
- **Server 决定 lease 有效性** (Client 不能按本机时钟续约/回收)
- **opaque lease identity** (Server 生成, Client 不能伪造)
- **owner epoch fencing** (旧 epoch 迟到 release / renew 不能影响新 epoch)
- **idempotency key** (重复请求用同 request_id 不双扣)
- **wire schema 跨语言** (Python 字段不能直接序列化, 用 stable 值)
- **主包零 Cluster / Redis 依赖**

## 2. 业务能力与边界 (SRP / OCP)

### 2.1 业务边界

- **主包 (sentinel)**: 提供 `TokenService` Port + `LocalTokenService` 默认实现
  (永远 LOCAL_GRANTED); 零 Cluster / Redis 依赖
- **集群 wheel (sentinel-cluster)**: 提供 `RemoteTokenService` (Protocol 代理) +
  Server (有状态资源分配) + Embedded Server (本地 sidecar 模式) + 启动形态选择
- **M6.5.7 envelope**: Server 自身的心跳 / 状态 / 故障事件走 M6.5.7 通道
  (依赖 cfe25a0 envelope V1 frozen)
- **主包不 import 集群 wheel 任何 symbol** (DIP 依赖倒置)

### 2.2 唯一职责

| 角色 | 职责 | **不**做 |
| --- | --- | --- |
| 主包 `TokenService` Port | 抽象 acquire / release 接口 | **不**知道协议 / 网络 / 集群 |
| 主包 `LocalTokenService` | 单进程永远 LOCAL_GRANTED | **不**有任何状态机 / 限流逻辑 |
| 集群 `RemoteTokenService` (Client) | Protocol 映射 + deadline + cancel + 鉴权 + 错误翻译 | **不**实现 Server 资源分配逻辑 |
| 集群 Token Server | 资源分配状态机 + lease 有效性 + 唯一时间权威 | **不**是 RuleSource / 不持久化规则 |
| Embedded Server | 在进程内启动 Server (单 worker 宿主) | **不**支持多 worker 隐式选主 |

### 2.3 数据归属

| 数据 | 归属 | 谁读 | 谁写 |
| --- | --- | --- | --- |
| 资源配额 (`resource -> max_permits`) | Server | Server, Cluster config | Server 启动时 from config, 不运行时改 |
| Lease (`lease_id -> (resource, permits, expires_at_ns, owner)`) | Server | Server | Server (allocate / renew / expire) |
| Owner epoch (`instance_id -> startup_epoch`) | Server | Server | Server (instance_id 首次出现时 from client) |
| Client request id (idempotency) | Server (短期 cache) | Server | Server 收到 request 时 record |
| `Token` (Python 投影) | Client | Client (FlowSlot release 时用) | Client 收到 Server `ACQUIRE_RESPONSE` 时构造 |
| `TokenResponse` (Python 投影) | Client | Client | Client 收到 Server 响应时构造 |

## 3. 同步能力 vs 异步事实响应 (DIP)

### 3.1 同步能力 (M6.3 Client 协议代理)

- "拿 cluster 准入" (`RemoteTokenService.acquire(resource, permits)`) → **同步**
- "释放 permit" (`RemoteTokenService.release(token)`) → **同步**

### 3.2 异步事实响应 (M6.5.7 envelope 通道)

- "Server 资源被 Owner A 占满, Owner B 的 acquire 失败" → **异步事件**,
  走 M6.5.7 `RULE_SOURCE_STALE` (类比, 但本质是 cluster resource 状态,
  不属于 Source); 实际 M6.3.6 用 Client-side 错误码
  `REMOTE_UNAVAILABLE` 等, **不**滥用 envelope 通道
- "Token Server 进入 FAIL_OPEN 降级" → **异步事件**, 走 M6.5.7
  `RULE_SOURCE_DEGRADED` (用 source_id = `cluster-token-server` 占位)

### 3.3 关键约束 (PLANNING §M6.3 验收)

- **禁止使用进程内 map 偷渡 remote lease 状态** (M6.3.2)
- **禁止按 Uvicorn worker ordinal 选主、隐式自举、leader election、服务发现猜测 owner**
  (M6.3.5)
- **禁止默认静默放行** (M6.3.6): 每个集群资源必须显式选
  `ClusterFailurePolicy` 一项

## 4. 模式候选 (OOP 守门)

### 4.1 候选: 跨进程 Protocol (Port + 序列化)

- **位置**: `docs/protocols/CLUSTER_TOKEN_PROTOCOL.md` (M6.3.1 V1 frozen),
  配套 Python 投影在 `atlas-richie-contracts` 仓 (`atlas_richie.cluster.v1`)
- **为什么**: 跨语言 wire protocol (Python Client / Go Server / etc),
  schema 用 stable 字符串值, 不直接用 Python dataclass 序列化
- **当前会发生的问题**: 跨语言 Server 实施不知道 Python dataclass 字段
- **设计**: V1 frozen, 跟 M6.5.7 envelope 同一治理, 跨语言 contract test
- **收益**: 1.x 末所有语言 SDK 实施都遵循同一 schema
- **误用防护**: V1 不可破坏性, 改走 V2 + ADR

### 4.2 候选: opaque lease identity (Server 决定)

- **位置**: M6.3.1 wire protocol + M6.3.2 `Token.lease_id` optional field
- **为什么**: Client 不能伪造 lease, 不能按本机时钟续约/回收; Server 是
  唯一时间权威
- **设计**: Server 收到 `ACQUIRE_REQUEST` 后, 检查 resource 配额, 分配
  `lease_id = uuid-string` (Server 进程内或外部 store 唯一), 写
  `(resource, permits, expires_at_ns, owner_instance_id, owner_epoch)` 状态;
  返回 `ACQUIRE_RESPONSE` 含 `lease_id`
- **收益**: 跨进程 lease 状态一致, 不可伪造
- **误用防护**: 禁止用进程内 map 偷渡; Server 状态必须可持久化 (defer M6.3.x future,
  1.0 用进程内 store + 显式声明)

### 4.3 候选: owner epoch fencing (stale-owner protection)

- **位置**: M6.3.1 `startup_epoch` 字段 (同 M6.5.7 envelope)
- **为什么**: 旧 epoch 的迟到 release / renew 不能影响新 epoch 已持有的 lease
  (例: Owner 进程 crash, 重启后 startup_epoch 变化, 旧 token 还在用,
  释放时不能影响新 owner 的 lease)
- **设计**: Server 收到 `RELEASE_REQUEST` / `RENEW_REQUEST` 时, 校验
  `(lease_id, owner_instance_id, owner_epoch)` 三元组; 不匹配 → 拒绝
  (返回 `STALE_EPOCH` 错误码, Client 忽略, **不**抛异常)
- **收益**: stale owner 不会双扣 / 串扰
- **误用防护**: `STALE_EPOCH` 是正常的 race 现象, 不该被视作 bug
  上报; Client 仅做日志 warn

### 4.4 候选: idempotency key (request_id 重用)

- **位置**: M6.3.1 `request_id` 字段 (UUID v4, Client 端生成)
- **为什么**: 网络重试不会双扣; 重复 release 不会报错
- **设计**: Client 端为每个 logical 操作生成唯一 `request_id`; 重试
  (网络失败) 用同 `request_id`; Server 端短期 cache (e.g. 5 min TTL)
  `(request_id -> response)`; 命中 cache 直接返回上次响应
- **收益**: at-least-once 投递 + 强幂等
- **误用防护**: cache TTL 必须 < lease TTL, 否则旧 lease 释放会
  错误命中 stale cache

### 4.5 候选: 启动形态 (Standalone vs Embedded) 显式区分

- **位置**: M6.3.5
- **为什么**: 多 worker 应用的所有 worker 都是 Client, 不能隐式自举 Server
  (会出现 lease 状态分裂)
- **设计**: 部署显式配置 `cluster_token_mode: standalone | embedded | client_only`;
  standalone 跑独立进程; embedded 只在单 worker 宿主启 Server
  (启动时 assert `worker_count == 1`); client_only 永远只做 Client
- **收益**: 避免 worker 选主 / leader election / 服务发现猜测
- **误用防护**: 启动时校验 + 运行时 fail-fast (worker 切换立即
  REMOTE_UNAVAILABLE)

### 4.6 候选: 弃用 — 通用 Service Mesh / Sidecar 抽象

- **理由**: PLANNING §M6.3 明确不引入 Service Mesh 抽象; wire protocol
  是专用契约, 不复用 Istio / Linkerd 通用 mesh

### 4.7 候选: 弃用 — 进程内 map 偷渡 remote lease 状态

- **理由**: 显式禁止 (PLANNING §M6.3.2 + M6.3.5); 跨进程状态分裂

## 5. 公开 API surface 变更 (1.0 兼容)

### 5.1 新增 (M6.3.2 评审 + 扩展 `ports/token.py`)

#### `Token` 加 2 个 optional field (有安全默认值)

```python
@dataclass(frozen=True, slots=True)
class Token:
    resource: str
    permits: float
    issued_at_ns: int
    ttl_ns: int
    # M6.3.2: opaque lease identity (Server 生成, 1.0 主包 LocalTokenService 永远 None)
    lease_id: Optional[str] = None
    # M6.3.2: owner epoch (fencing, 1.0 主包 LocalTokenService 永远 None)
    owner_epoch: Optional[int] = None
```

**安全默认值**: `lease_id=None` + `owner_epoch=None`. LocalTokenService
构造时**不**填这两个字段 (保持 1.0 行为不变). 集群 wheel RemoteTokenService
收到 Server `ACQUIRE_RESPONSE` 时填入.

#### `TokenResponse` 加 1 个 optional field

```python
@dataclass(frozen=True, slots=True)
class TokenResponse:
    decision: TokenDecision
    token: Optional[Token] = None
    deny_reason: Optional[TokenDenyReason] = None
    wait_ns: int = 0
    # M6.3.2: Server 建议重试延迟 (区分 client-side vs server-side wait)
    retry_after_ns: int = 0
```

**安全默认值**: `retry_after_ns = 0`. LocalTokenService 不填 (永远 0).

#### 新增 `ClusterFailurePolicy` enum (M6.3.6)

```python
class ClusterFailurePolicy(StrEnum):
    """Cluster 资源 acquire 失败时的策略 (M6.3.6)。"""
    FAIL_CLOSED = "fail_closed"      # 实际 grant 不超 Server 配额 (强保证)
    FAIL_OPEN = "fail_open"          # 不承诺不超发, 但每次放行有可查询决策
    LOCAL_FALLBACK = "local_fallback"  # 显式配置本地策略, 不伪装共享配额
```

**位置**: `sentinel.ports.token.ClusterFailurePolicy` (跟 TokenDecision / 
TokenDenyReason 同一个文件, 1.0 兼容).

### 5.2 新增 (集群 wheel `sentinel-cluster/`)

- `RemoteTokenService` (TokenService Protocol 实现, 走 CLUSTER_TOKEN_PROTOCOL)
- `TokenServer` (有状态资源分配状态机)
- `EmbeddedTokenServer` (单进程内启 Server, 跟 Engine 同生命周期)
- `ClusterTokenConfig` (frozen dataclass: server_addresses / tls / failure_policy
  per resource / request_timeout_ns / reconnect_initial / reconnect_max)

### 5.3 不变 (1.0 主包公开 API)

- `TokenDecision` / `TokenDenyReason` 枚举值不变
- `Token` 既有 4 个 field 不删 / 不改名 (新加 2 个 optional, 旧构造方式兼容)
- `TokenResponse` 既有 4 个 field 不删 / 不改名 (新加 1 个 optional)
- `TokenService` Protocol 签名不变
- `LocalTokenService` 行为完全不变

### 5.4 1.0 兼容验证

- 旧代码 `Token(resource=..., permits=..., issued_at_ns=..., ttl_ns=...)` 
  仍 work (新字段用默认值)
- 旧代码 `TokenResponse(decision=..., token=..., deny_reason=..., wait_ns=...)`
  仍 work
- LocalTokenService 永远不构造 `lease_id` / `owner_epoch`, 保持单进程语义
- 单元测试 + 集成测试覆盖新增字段

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| V1 frozen 后, 新需求走 V2 ADR (慢) | 1.x 末新功能上线慢 | V1.1 minor 允许加 optional field / 新 message_kind; V2 仅破坏 V1 兼容走 |

| 跨语言 SDK 实施错误 | wire 协议字段不一致 | M6.3.7 contract test 强制 Python 序列化 round-trip + 至少 1 个其他语言 SDK mock |
| owner epoch fencing 误判 | 误拒正常 release | STALE_EPOCH 是正常 race, Client 仅日志 warn, 不抛异常 |
