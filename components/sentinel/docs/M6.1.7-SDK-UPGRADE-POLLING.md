## 1. 背景与动机

M6.1.0-1.6 实施基于 **错误假设**: 以为 `nacos-sdk-python` 是 2.x, 接受 tuple
`server_addresses`、提供 V1 `publish_config` / `get_config` / `add_config_watcher`
同步 API。实际情况 (M6.1.7 spike 验证):

| 项 | M6.1.0-1.6 假设 | 实际 (lockfile 锁) |
| --- | --- | --- |
| SDK 版本 | "2.x" | `nacos-sdk-python==2.0.11` (PyPI), `__version__="0.1.16"` (代码未改) |
| `server_addresses` 参数类型 | tuple / list | **str** (`.strip()` 调用, 传 list 直接 `AttributeError`) |
| `publish_config` 协议 | V1 HTTP `/nacos/v1/cs/configs` | Nacos 3.x **删了 V1 endpoint** → 404 No endpoint |
| listener 刷新协议 | SDK 内 long-poll HTTP | SDK 3.2.0 使用 gRPC streaming；当前部署未完成可靠 callback 验证，因此不作为正确性路径 |
| 实际兼容的 Nacos server | 假设 1.x/2.x 全部 | Nacos 3.2.3 的 config publish/query 与 polling 已真实验证 |

**两个 P0 bug**:
1. **构造层** (`_NacosAdapter._build`): 传 `list(cfg.server_addresses)` 给 SDK, 真实 SDK 抛 `AttributeError`。M6.1.7.1 修 (改 `",".join(...)`)。
2. **协议层**: SDK 0.1.16/2.0.11 的旧 V1 假设不能覆盖 Nacos 3.x；升级至 SDK 3.2.0 后，config publish/query 已在 Nacos 3.2.3 验证。listener 不进入正确性合同，刷新统一采用 polling。

## 2. 设计决定 (5 项)

### D1. 升级 nacos-sdk-python 0.1.16 → 3.2.0

- 包名不变 (`nacos-sdk-python`), 模块路径变 (`nacos` → `v2.nacos`)。
- 公开 API 变: `NacosClient(server_addresses, ...)` 同步 → `NacosConfigService.create_config_service(ClientConfig)` async + `NacosConfigService.get_config(ConfigParam)` async。
- pyproject 依赖: `nacos-sdk-python>=2.0,<3.0` → `nacos-sdk-python>=3.0,<4.0`。
- 适配层 `_NacosAdapter` 改为 async (但**外层** `NacosRuleSource.snapshots()` 仍 async iterator; SDK 调用在 `_NacosAdapter` 内部, 不暴露 async 给协议)。

### D2. 改 push 模式为 polling 模式 (核心架构改造)

**原架构 (M6.1.0-1.6)**:
```
SDK long-poll push → Nacos SDK 内部 callback (cb(params)) 
  → _on_sdk_change (marshal 到 asyncio.Event) 
  → snapshots() 循环 await _change_event.wait() 
  → 重新拉 5 个 data_id → 跟上次比对 → yield
```

**新架构 (M6.1.7)**:
```
NacosRuleSource.snapshots() 启动
  → asyncio.create_task(_poll_loop()) 后台 task
  → 每 poll_interval 秒:
    1. _NacosAdapter.fetch_all() 拉 5 个 data_id (async, await)
    2. decode_rule_snapshot() → new_snapshot
    3. checksum 比对 (跟 self._last_yielded_version)
    4. 变化 → 写 pending snapshot 并唤醒 iterator；iterator 在实际 yield 前更新 _last_yielded_version
    5. 无变化 → skip
  → 错误分类: NETWORK → 退避, 其它 (NOT_FOUND/EMPTY/DECODE) → STALE 保留 last-known-good
  → aclose() 取消 _poll_task, 关闭 SDK
```

**公开 API 不变**:
- `snapshots() -> AsyncIterator[RuleSnapshot]` 协议签名不变
- 行为变化: snapshot yield **最多**每 `poll_interval` 秒一次 (默认 1s), 不会"准实时" (push 通常 < 100ms)
- trade-off: 资源开销高 (每秒 5 个 get_config); 实时性从 < 100ms 降到 ≤ 1s; 兼容 Nacos 3.x

### D3. 新增 `NacosRuleSourceConfig.poll_interval` 字段

- 类型: `timedelta`, 默认 `1 second`
- `__post_init__` 校验: `> 0`, `>= 100ms` (避免误用 0 触发 hot loop)
- 影响 5 类 default-deny 中的 "资源上限" 类: 由 ADR-SEN-007 追加签字 (本设计文档 D7 节)
- 不影响 1.x 已锁定的 9 个公开 symbol (PLANNING §M6.1.6 公共 API 表)

### D4. 适配层内部异步化, 协议层不变

- `_NacosAdapter.fetch_all()` 从 `async def fetch_all() -> ...` 改为 async (沿用), 但**内部 SDK 调用**:
  - 旧 (M6.1.0-1.6): `await loop.run_in_executor(None, client.get_config, ...)` 包装同步 SDK
  - 新 (M6.1.7): `await client.get_config(ConfigParam(...))` 直接 await async SDK
- `_NacosAdapter.aclose()` 旧: `run_in_executor`; 新: `await svc.shutdown()`
- `_NacosAdapter.register_watchers()` **删除** (不再需要 long-poll listener)

### D5. 重写 `_FakeNacosClient` mock

- 旧 mock 模拟 SDK 0.1.16 同步 API (`get_config` / `add_config_watcher` / `stop_subscribe`)
- 新 mock 模拟 SDK 3.2.0 async API (`get_config` / `publish_config` / `add_listener` 仍保留但不触发 / `remove_config` / `shutdown` / `server_health` / `create_config_service` factory)
- 异步化: 所有 mock 方法 `async def`; 但**可选**模拟 SDK 行为 (不主动触发 listener, 等 polling 检测到变化)
- 测试策略变化: 旧测试"trigger_change → 验证 yield 新 snapshot" 改为 "set_config → sleep poll_interval → 验证 yield 新 snapshot"

### D6. (隐含) C 层 / B 层治理保持

- `NacosRuleSource` 不 import 主包 `_supervisor.*` (沿用 M6.1.0 P1 #2)
- 5 类错误分类 + 状态机 + 退避 + 脱敏 **不**变
- `aclose()` 幂等保证 **不**变
- `RuleSourceActivation` 内部 fact 不含时间戳 (沿用 M6.1.0 P1, M6.5.7 冻结)

### D7. default-deny 5 类影响: 资源上限追加签字

`poll_interval` 字段影响 "资源上限" 类 (每秒 5 个 get_config = 5 QPS/Source),
按 M6.1.0 API delta v3 决策 5, 需 ADR-SEN-007 追加签字栏:

```text
+ ADR-SEN-007 追加: NacosRuleSourceConfig.poll_interval 资源上限
  - 上限: 最低 100ms (防 hot loop)
  - 上限: 默认 1s (跟 Java sentinel-datasource-nacos 行为近似)
  - 用户可调, 但需显式声明
```

## 3. 公开 API surface 变更 (新 vs 旧)

| 公开符号 | M6.1.0-1.6 | M6.1.7 | 兼容 |
| --- | --- | --- | --- |
| `NacosRuleSource` | class | class (内部 polling 改造) | ✅ |
| `NacosRuleSource.snapshots()` | async gen (push 触发) | async gen (poll 触发) | ✅ 协议不变 |
| `NacosRuleSource.aclose()` | async (幂等) | async (幂等, 取消 poll_task) | ✅ |
| `NacosRuleSource.source_id` | str | str | ✅ |
| `NacosRuleSource.state` / `last_error*` / `error_count` | 同 M6.1.2 | 同 M6.1.2 | ✅ |
| `NacosRuleSourceConfig.source_id` | str | str | ✅ |
| `NacosRuleSourceConfig.server_addresses` | `tuple[str, ...]` | `tuple[str, ...]` (适配层拼接 str) | ✅ |
| `NacosRuleSourceConfig.namespace` / `group` / `data_id_prefix` | str | str | ✅ |
| `NacosRuleSourceConfig.auth` / `tls` | Optional | Optional | ✅ |
| `NacosRuleSourceConfig.connect_timeout` / `read_timeout` | timedelta | timedelta | ✅ (transport 用 grpc_timeout 替代) |
| `NacosRuleSourceConfig.reconnect_initial` / `reconnect_max` | timedelta | timedelta | ✅ |
| **`NacosRuleSourceConfig.poll_interval`** | (无) | **timedelta, default 1s, >= 100ms** | 🆕 新增 |
| `NacosRuleSourceConfig.data_id_for()` | method | method (不变) | ✅ |
| `NacosAuth` / `NacosTLS` / `NacosSourceState` / `NacosSourceError` | 同 M6.1.2 | 同 M6.1.2 | ✅ |
| `NacosCallbackParams` (内部 type alias) | 暴露 | **不**暴露 (无 push 不需要) | ⛔ 删除 |

**总评**: 公开 API surface 净增 1 个字段 (`poll_interval`), 删除 1 个内部 type
(`NacosCallbackParams`, 之前未进 `__all__`, 无用户感知), 8 个方法签名不变,
5 个枚举 / 值对象不变。**1.0 兼容**。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| SDK 3.2.0 升级引入新 bug | 1.0 publish 失败 | M6.1.7.7 跑完整 unit test + M6.1.7.10 跑 5 场景集成 |
| polling 1s 间隔不符合"近实时"语义 | Java sentinel-datasource-nacos 行为 < 100ms | 默认 1s 是 P99 实时; 用户可调 `poll_interval=100ms` (合法下限) |
| 每秒 5 个 get_config = 5 QPS/Source | 多 Source 时 Nacos server 压力大 | `poll_interval` 暴露给用户调; 默认 1s 跟 Java 默认近似 |
| SDK 3.2.0 lockfile 漂移 | uv lock 重生成时可能拉 4.0 (breaking) | 锁 `>=3.0,<4.0` 范围 + lockfile 跟 pyproject 同步 |
| 1.0 文档未说明 polling 行为 | 用户期望 push 模式 | M6.1.7.12 文档加 polling 节 + 5 场景验证清单 |
| `NacosCallbackParams` 删了, 任何 extension import 它 | 1.x 内部 compat 失败 | M6.1.0 没在 `__all__` 暴露, 0 用户影响; grep 确认无外部引用 |
