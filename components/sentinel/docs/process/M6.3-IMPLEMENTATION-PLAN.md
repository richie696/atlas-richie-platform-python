## 1. 实施决策备忘 (Mavis 想清楚, worker 照做)

> 这部分是把"实施阶段没在 design 文档里规定"的关键决策列清楚, 防止 worker 拍脑袋。worker 任务 prompt 必须包含本节。

### 1.1 wire transport (M6.3.4 决策)

**决策**: HTTP/1.1 + JSON over TCP, 用 `asyncio.start_server` + 手动解析 HTTP request line + Content-Length 头。

**理由**:
- 不引入 gRPC / HTTPX 依赖 (主包 0 依赖 + Cluster wheel 也 0 3rd-party 约束, M6.1.0a ADR-SEN-001 决策)
- 单连接 + 单请求 + 单响应 (request/response 模式, 无 server-push, 协议 §1 已冻结)
- envelope size ≤ 8 KB, Content-Length 足够, 不需要 chunked / stream
- asyncio 原生支持, 跟 Engine event loop 兼容
- 跨语言 SDK 容易实施 (Go net/http, Java HttpServer, Node http)

**反例**: 
- ❌ 不用 `aiohttp` (避免 3rd-party)
- ❌ 不用 gRPC (避免 3rd-party, 跨语言 schema 复杂)
- ❌ 不用 WebSocket (协议是 request/response, 不要 push 语义)

### 1.2 Server 进程内 store (M6.3.3 决策)

**决策**: 进程内 `dict[resource -> State]` + `dict[lease_id -> Lease]` + `dict[request_id -> Response]` (5 min TTL), 用 `asyncio.Lock` 保护 (Server 是单 event loop)。

**理由**:
- 1.0 接受限制: "Server 重启期间 active lease 失效" (设计 §8 风险)
- 持久化留 M6.3.x future (Redis HA 另起 ADR, 跟 Cluster wheel 0 依赖约束一致)
- asyncio.Lock 而非 threading.Lock (Server 在 asyncio 进程里, 跟 Engine event loop 一致)

**Lease 默认 TTL**: 30 s (协议 §5.2 推荐)

**idempotency cache TTL**: 5 min (协议 §5.1 冻结, < lease TTL)

### 1.3 鉴权 (M6.3.4 决策)

**决策**: 1.0 用 shared secret, HTTP header `X-Atlas-Cluster-Token: <secret>`, Server 启动时校验。

**理由**:
- mTLS / OAuth 留 M6.3.x future (避免 1.0 引入证书管理 / token endpoint)
- shared secret 简单, 1.0 用户基线是"内网部署 + 同 VPC"
- 缺失 token 头 → 401 + `INTERNAL_ERROR` + ClusterFailurePolicy 决策
- 错误 secret → 401 + 同上

**M6.5.7 envelope 集成** (M6.3.6): Server 进入 FAIL_OPEN 降级时, 异步事件 `RULE_SOURCE_DEGRADED` (source_id = `cluster-token-server` 占位)。

### 1.4 启动形态 (M6.3.5 决策)

**决策**: `ClusterTokenConfig.cluster_token_mode: StrEnum = "standalone" | "embedded" | "client_only"`, 启动时严格 assert。

**standalone**: 独立进程 (`python -m atlas_richie.sentinel_cluster.server`), 仅 `__main__` 入口。

**embedded**: 进程内启 Server, 启动时 `assert worker_count == 1` (读 `SERVER_WORKER_COUNT` env 或 uvicorn `--workers 1` 强制)。多 worker 直接 fail-fast。

**client_only**: 永远只连外部 Server, 启动时校验 `server_addresses` 非空。

**反例**:
- ❌ 不用 worker ordinal (`os.getpid() % N == 0`) 选主
- ❌ 不用 leader election (etcd / redis lock)
- ❌ 不用服务发现自动找 Server (避免隐式依赖)

### 1.5 ClusterFailurePolicy per resource (M6.3.6 决策)

**决策**: `ClusterTokenConfig.failure_policy_per_resource: dict[str, ClusterFailurePolicy]`, 每个 cluster resource **必须**显式配置 1 项, 不在 dict 里的 resource → 启动 fail-fast (M6.3.6 验收不变量)。

**语义**:
- `FAIL_CLOSED` (强保证, 默认): Server unreachable / 拒响应 → deny (TokenResponse.decision=DENIED, deny_reason=REMOTE_UNAVAILABLE)
- `FAIL_OPEN` (不承诺不超发): Server unreachable → grant local stub token (token.lease_id=None 标记 stub), 每次放行产生 `FAIL_OPEN_DECISION` 指标 (M6.5.7 envelope 通道, 1.0 留 stub 计数, 完整指标留 M6.5.1-6)
- `LOCAL_FALLBACK` (显式本地策略): Server unreachable → fallback 到 LocalTokenService (永远 LOCAL_GRANTED, 但不伪装共享配额; 指标加 `LOCAL_FALLBACK_DECISION`)

**反例**:
- ❌ 不用 default-deny 之外的"auto / silent / inherit"
- ❌ 不用 worker 级全局 policy (每个 resource 必须显式)
- ❌ 不用 fail_open 默认 (1.0 默认是 fail_closed, 强保证)

### 1.6 Python 投影位置 (Mavis 决策)

**决策**: wire protocol 6 message_kind 的 Python dataclass 投影放在 `foundation/contracts/src/atlas_richie/contracts/cluster/v1/`, **不**在 `sentinel-cluster` 仓 (避免 sentinel-cluster 仓自身 `atlas_richie.contracts` 依赖, M6.1.0a PEP 508 transitive resolve 决策)。

**sentinel-cluster** 仓 `dependencies` 仅声明:
- `atlas-richie-sentinel` (主包)
- `atlas-richie-contracts` (协议投影, 1.0 publish 前必须先发)

**contracts 仓** 是 Foundation wheel, 比 cluster 更基础; `atlas_richie.contracts.cluster.v1` 是 Python 投影, 不引入额外 3rd-party。

### 1.7 与 M6.5.7 envelope 集成 (M6.3.6 决策)

**Server 触发 M6.5.7 envelope 事件** (1.0 stub, 完整 M6.5.1-6 实施):
- `RULE_SOURCE_DEGRADED` (source_id=`cluster-token-server`): Server 进入 FAIL_OPEN 降级时
- `RULE_SOURCE_STALE` (source_id=`cluster-token-server`): Server lease 状态机异常时

**Client 触发 M6.5.7 envelope 事件** (1.0 stub, 完整 M6.5.1-6 实施):
- `RULE_SOURCE_STALE`: Client 收到 STALE_EPOCH 错误码时 (正常 race, 标 warn 不抛)

1.0 stub 行为: 只调用 `metrics.counter("cluster.event", tags={"kind": ...}).inc()` (主包 metric), 不实际投递 envelope; 完整投递留 M6.5.1-6 worker 实施。

### 1.8 错误码映射 (M6.3.4 决策)

Client 收到 `ErrorResponsePayload` → 转 `TokenResponse(decision=DENIED, deny_reason=...)` 或抛 `SentinelError` 子类:

| Wire error_code | Client 处理 | TokenResponse 字段 |
| --- | --- | --- |
| `PROTOCOL_VERSION_MISMATCH` | retry 无效, 标 ClusterFailurePolicy | `deny_reason=REMOTE_UNAVAILABLE` |
| `MALFORMED_ENVELOPE` | log error, 标 ClusterFailurePolicy | `deny_reason=REMOTE_UNAVAILABLE` |
| `UNKNOWN_MESSAGE_KIND` | retry 无效, 标 ClusterFailurePolicy | `deny_reason=REMOTE_UNAVAILABLE` |
| `STALE_EPOCH` | log warn, **不**抛异常 | `deny_reason=REMOTE_UNAVAILABLE` (Client 端无影响) |
| `LEASE_NOT_FOUND` | log warn, lease 已过期 | (release 无响应, 业务继续) |
| `LEASE_EXPIRED` | log warn, 需重新 acquire | (renew 无响应, 业务继续) |
| `RESOURCE_NOT_CONFIGURED` | fail-fast 启动期就报 | `deny_reason=RESOURCE_NOT_CONFIGURED` |
| `SERVER_OVERLOADED` | 按 ClusterFailurePolicy | `deny_reason=SERVER_OVERLOADED` |
| `INTERNAL_ERROR` | retry 一次, 仍失败按 ClusterFailurePolicy | `deny_reason=REMOTE_UNAVAILABLE` |

**新增 TokenDenyReason 值** (M6.3 评审 + 1.0 兼容扩展):
- `REMOTE_UNAVAILABLE` (Server 不可达 / 协议错误)
- `RESOURCE_NOT_CONFIGURED` (部署错误, 启动期 fail-fast)
- `SERVER_OVERLOADED` (Server 资源满, DENIED)

加在 `sentinel/ports/token.py` 现有 `TokenDenyReason` enum (1.0 兼容: 加新值, 不删不改既有)。

### 1.9 测试治理

- **单元测试**: 不依赖真实 network / Server, 用 `pytest-asyncio` + mock
- **集成测试**: 启真 Server (同一进程), Client 走 socket, 跑全 9 类场景
- **contract 测试**: 协议字段值 round-trip (JSON 序列化反序列化一致), 跨语言 mock 1.0 publish 前 worker 跑 (Go / Java mock 1 个至少)

### 2.4 TokenServer 状态机状态表 (Worker 必须实现)

| 状态 | 转换触发 | 下一状态 | 动作 |
| --- | --- | --- | --- |
| `CREATED` | `await token_server.start()` | `READY` | 初始化 lease_store + idempotency_cache + http_transport.listen |
| `READY` | 收到 ACQUIRE_REQUEST 且 resource 配额未满 | `READY` (in-place) | 分配 lease_id (UUID v4), 写 lease_store, 返回 REMOTE_GRANTED |
| `READY` | 收到 ACQUIRE_REQUEST 且 resource 配额满 | `READY` (in-place) | 返回 DENIED + deny_reason=QUEUE_FULL |
| `READY` | 收到 RELEASE_REQUEST 且 `(lease_id, instance_id, startup_epoch)` 匹配 | `READY` (in-place) | 删 lease_store entry, 配额恢复 |
| `READY` | 收到 RELEASE_REQUEST 且不匹配 | `READY` (in-place) | 返回 ERROR_RESPONSE STALE_EPOCH (不抛) |
| `READY` | 收到 RENEW_REQUEST 且 lease 未过期 + epoch 匹配 | `READY` (in-place) | 延长 expires_at_ns, 返回 RENEWED |
| `READY` | 收到 RENEW_REQUEST 且 lease 已过期 | `READY` (in-place) | 返回 DENIED + deny_reason=LEASE_EXPIRED |
| `READY` | lease expires_at_ns 到了 (后台 task 扫) | `READY` (in-place) | 删 lease_store entry, 配额恢复 |
| `READY` | `await token_server.stop()` | `SHUTTING_DOWN` | 停止 http_transport.listen (新连接拒), 等 in-flight 请求 |
| `SHUTTING_DOWN` | in-flight == 0 | `SHUTDOWN` | 释放资源 |
| `SHUTTING_DOWN` | shutdown_timeout (默认 5s) 触发 | `SHUTDOWN` (强制) | 取消 in-flight (返回 SERVER_OVERLOADED 错误码) |
| `READY` | 启动时 resource 未在 config 中配置 | (启动失败) | fail-fast 抛 `ClusterConfigError("RESOURCE_NOT_CONFIGURED")` |

### 2.5 `__main__` 入口 (Standalone)

`python -m atlas_richie.sentinel_cluster` 等价 `python -m atlas_richie.sentinel_cluster.server.standalone`, 接收 CLI 参数:
- `--bind 0.0.0.0:8765` (默认)
- `--config /path/to/cluster.yaml` (YAML 描述 `ClusterTokenConfig`, **不**用裸 dict)
- `--shutdown-timeout 5.0` (默认)

YAML schema 跟 `ClusterTokenConfig` 一一对应; 1.0 接受 YAML, 拒绝裸 dict (default-deny 决策)。

**注意**: 不引入 `pyyaml` 到主包依赖; YAML 解析用 Python stdlib? 1.0 stdlib **没有** YAML。**决策**: 1.0 Cluster config 只支持 Python 显式构造 (`ClusterTokenConfig(...)`), 不支持 YAML; CLI 入口只接 `--config` JSON 文件 (stdlib `json`)。YAML 支持留 M6.3.x future (用户自带 `pyyaml` 转 dict 再 `**dict` 给 config)。

### 4.3 Public API 表面

`RemoteTokenService` 签名 (1.0 兼容, 跟 M6.3.2 Port 一致):

```python
class RemoteTokenService:
    def __init__(
        self,
        config: ClusterTokenConfig,
        *,
        identity: ClientIdentity,  # frozen dataclass: instance_id (UUID) + startup_epoch (int)
    ) -> None: ...
    
    async def start(self) -> None: ...  # 连接池 / 重连初始化
    
    async def aclose(self) -> None: ...  # 关闭连接池
    
    def acquire(
        self, resource: str, permits: float
    ) -> TokenResponse:
        """同步 facade (1.0 跟 LocalTokenService 一致).
        
        内部协程化: 用 asyncio.run_coroutine_threadsafe 或新 event loop (M6.3.4 决策).
        """
    
    def release(self, token: Token) -> None:
        """同步 facade.
        
        1.0 release 永远 best-effort: 失败仅 log warn, 不抛异常.
        """
```

**Client 端 acquire/release 同步 facade** 决策 (Mavis 决策, 跟 M6.7 评估一致):

`TokenService.acquire` Port 签名允许返回 `Awaitable[TokenResponse]` (M6.3.2 §8 已冻结), `RemoteTokenService` 实现**同步 facade**:

- 内部用 `asyncio.new_event_loop()` + `loop.run_until_complete(...)` 一次, 不在 event loop 已运行时调用
- **不**复用以 Engine event loop (M6.7 决策: 跨线程 / 跨 loop 行为未定义, 1.x 不支持)
- p99 性能基线 < 1ms (本地 127.0.0.1)

**反例**:
- ❌ 不用 `asgiref.sync_to_async` (1.0 不引入)
- ❌ 不用线程池共享 event loop (M6.7 决策: 跨线程行为未定义)
- ❌ 不用 `nest_asyncio` (违反 1.x 同步合同)
