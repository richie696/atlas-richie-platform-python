# T03.4 / T03.5 Console API 0.9.0 implementation test plan

Status: implementation plan for the approved joint API 0.9.0 contract.

This plan covers additive read paths only. Console API 0.8.0, Collector
Reporting V1, Agent Reporting V1, Runtime Receipt V1, Metrics V2, and source
refresh/write behavior remain unchanged. Full browser E2E remains T07.1.

## Execution order

1. Record the approved 0.9.0 deltas, then implement typed domain queries and
   application read ports.
2. Add SQL readers and migrations only where existing durable facts cannot
   express the approved projection. Do not duplicate inbox/current-state tables
   or reimplement provider adapters.
3. Add authenticated HTTP routes, strict serializers, and OpenAPI.
4. Add React DTO validation, gateway, application resources, and page state
   consumption. Keep wire DTOs out of components and preserve local drafts.
5. Run focused unit/API/SQLite tests first; run disposable PostgreSQL/MySQL
   parity next; run provider acceptance only with the existing safe harness and
   exact cleanup. Full browser E2E stays at T07.1.

## Closure rule

Neither task closes on compilation or fixtures alone. T03.4 requires provider,
SQL, API, and mounted-page evidence for its state matrix. T03.5 requires durable
Collector facts, SQL denominator/freshness parity, authenticated API, and
mounted-page evidence. An unavailable provider/database boundary is reported
as open, not silently converted to a pass.
