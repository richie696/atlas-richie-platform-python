**Design authority:** `ADR-SEN-020` (product-owner authorization 2026-10-14).
**Scope of this slice:** typed snapshot + JSON Schema/codec + shared Python,
Java, and Go fixtures. This is not Reporter/Collector, SQL, or browser E2E
acceptance.

## Slice close criteria

- Python codec, Java validator, and Go validator pass exactly the same valid and
  invalid fixture files.
- JSON Schema agrees with the codec for all expressible structural limits;
  duplicate-key and aggregate array-length checks remain codec assertions.
- Historical draft-only validators are not described as production SDKs.
- This slice must not change Reporting V1 or Console OpenAPI 0.4.0.

## T04.1 Reporter test design

| ID | Risk | Test layer and required proof |
|---|---|---|
| MET-RPT-001 | Producer metrics are mapped to the wrong V2 meaning/unit/scope | Pure mapper tests for HTTP completed responses, admitted/blocked Sentinel entries, process-only CPU/RSS/memory/loop-lag gauges, and absence of inferred TPS; unsupported or absent inputs stay unavailable. |
| MET-RPT-002 | Existing histogram profile or record bounds silently corrupts V2 | Reject non-frozen HTTP bounds; enforce at most 256 records and 256 active resource identities without truncation/eviction; retain exact cumulative counters and pooled buckets. |
| MET-RPT-003 | Reporter work leaks onto admission/response hot paths | Port contract tests prove synchronous bounded enqueue, short mutex only, capacity refusal, same-identity coalescing, and no transport invocation from `try_enqueue`. |
| MET-RPT-004 | Lost/uncertain ACK creates a new idempotency key or false success | Async reporter tests prove retries resend byte-identical payload with unchanged `(reporter_id, startup_epoch, sequence)`, validate receipt correlation/digest before dequeue, and advance sequence only after a valid durable receipt. |
| MET-RPT-005 | mTLS renewal is ignored or credentials leak | HTTP Adapter tests prove each connection generation uses the provider's current verified `SSLContext`, rotates connection pools safely, never adds bearer/proxy identity headers, and does not expose private material in repr/log/error text. |

The Reporter remains separate from Reporting V1. The core consumes the existing
`MetricsReportingPort`; only the HTTPX infrastructure Adapter performs network
I/O. Test doubles isolate Reporter scheduling and mapping; they do not prove
TLS handshake or durable Collector behavior, which remain T04.2 integration
gates.

## T04.2 Collector and durable SQL test design

| ID | Risk | Test layer and required proof |
|---|---|---|
| MET-COL-001 | Client-controlled identity or unverified proxy headers authorize ingest | ASGI/transport contract rejects absent, invalid, revoked, or cross-scope TLS principal; identity is resolved from a trusted transport certificate object and binds payload reporter identity to the enrolled application/environment/instance/process. |
| MET-COL-002 | Malformed/oversized snapshots reach persistence | HTTP boundary enforces the frozen body limit before buffering unbounded input; strict shared V2 decoder rejects unknown/duplicate/invalid fields with stable errors and no raw-body echo. |
| MET-COL-003 | ACK precedes durable commit | SQL adapter failure/commit failure produces no success receipt; a successful response is generated only after the transaction context exits successfully. |
| MET-COL-004 | Concurrent duplicate or changed bytes create duplicate history | Same authenticated `(reporter, epoch, sequence, digest)` returns the original persisted receipt; a different digest conflicts; concurrent exact duplicates produce one history write. |
| MET-COL-005 | Older sequence or regressing elapsed time corrupts baseline | An unreceipted older sequence and invalid same-epoch elapsed regression are rejected; a new epoch starts a new baseline; already-receipted replay is idempotent. |
| MET-COL-006 | SQLite/PostgreSQL/MySQL behavior drifts or dialect checks leak into use case | One shared adapter contract matrix runs against in-memory/temp SQLite and disposable PostgreSQL/MySQL; assert migration, atomic receipt+snapshot, rollback, restart readback, and no dialect branch in application Facade. |
| MET-COL-007 | Raw history or rollup is unbounded/non-repeatable | Explicit expiration honors 24-hour raw and 30-day UTC minute-rollup retention; repeated rollup/cleanup is idempotent and bounded; rejected inputs never create partial rows. |
| MET-COL-008 | Reporter identities can only be seeded by direct SQL or a revoked identity can be silently rebound | Application management Port + operator CLI enroll/revoke tests; persist only SHA-256 fingerprint and principal/scope, reject duplicate identity keys and revoked re-enrollment, make revoke idempotent, and never accept/log private-key material. Verify SQL readback and a subsequent real TLS POST. |
| MET-COL-009 | Process death after writes begin but before transaction commit leaves partial receipt or false ACK | Against SQLite and disposable PostgreSQL/MySQL, pause a spawned writer after its `console_metrics_snapshot` INSERT but before commit, terminate it, assert no success ACK and no binding sequence/epoch/snapshot changes, then replay the exact V2 body and assert one committed snapshot and one durable receipt. |
| MET-COL-010 | Revocation races an in-flight ingest and allows post-revocation acknowledgement | Two independent connections coordinate revoke and ingest against the same binding; assert database serialization: if revoke commits first, ingest gets no ACK; if ingest commits first, its committed receipt remains valid and subsequent requests are rejected. Run on SQLite plus disposable PostgreSQL/MySQL. |

The first implementation slice may close individual test cases but must not
check T04.2 until all required dialect, authentication, transaction, recovery,
retention, and enrollment/revocation criteria in the progress checklist have evidence. SQL tests use
synthetic identities and disposable, explicitly named data only; no shared or
production database is permitted.
