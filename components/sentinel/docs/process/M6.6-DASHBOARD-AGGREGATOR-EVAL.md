## 1. 范围与不在范围

### 1.1 实施范围

- `atlas-richie-sentinel-dashboard` extension wheel 升级 (替换 stdlib http.server):
  - 框架: Starlette (轻量 ASGI, 不引入 FastAPI 全套)
  - 模板: Jinja2 (HTML 页面)
  - ASGI server: uvicorn (开发) / hypercorn (生产, optional)
  - 静态文件: Starlette StaticFiles (CSS / JS / favicon)
  - 实时: SSE (Server-Sent Events) 每 5s 推 metrics
  - 鉴权: Bearer token (admin) — 跟现有保持一致
  - 审计: JSON list, capped 1000 (现有保留)
  - Bind: 127.0.0.1 默认 (loopback, M6.7 决策一致)
- **API 端点 (保留 6 个 JSON, 新增 HTML 页面)**:
  - 保留 JSON: `GET /health`, `/metrics`, `/rules`, `/rules/<id>`, `/state`;
    `POST /admin/rules/reload`, `/admin/breaker/<id>/reset`
  - 新增 HTML: `GET /` (dashboard overview), `/rules` (HTML), `/metrics` (HTML),
    `/settings`, `/audit`, `/sse/metrics` (SSE)
- **依赖 (extension wheel, 主包 0 3rd-party 不变)**:
  - `starlette >= 0.40, < 1.0`
  - `jinja2 >= 3.0, < 4.0`
  - `uvicorn >= 0.30, < 1.0` (dev); `hypercorn >= 0.16, < 1.0` (prod, optional)

### 1.2 明确不在范围 (Non-Goals)

- **不出** `sentinel-dashboard-aggregator` (跨进程聚合, 1.0 范围不含, 留 1.x 候选).
- **不出** Collector Python (Java/Go 服务端独立仓, V1 协议只冻结 wire contract).
- **不修改** 主包 (`atlas-richie-sentinel`) — 0 3rd-party 约束不变.
- **不引入** web framework 到主包或 1.x 任何 extension **除** dashboard.
- **不引入** 数据库驱动到 dashboard (1.0 用 in-memory metrics cache, 留 V2 持久化).
- **不评估** Grafana / OpenSergo Dashboard / Datadog 等外部产品的集成 (留给用户按需自建).

## 2. 关键设计

### 2.1 Boundary (边界 + 唯一职责)

- **职责**: 1 个 per-process Web 管理页面, 提供 HTML 视图 + JSON API.
- **不**承担: 跨进程聚合, 持久化, 复杂权限模型.
- **数据归属**:
  - 读取: SentinelEngine, MetricRegistry, RuleRepository (主包 1.0 公共 API)
  - **不**拥有: 规则数据 (RuleRepository 拥有), metrics 数据 (MetricRegistry 拥有)
  - 写入: 触发 RuleSource reload, DegradeSlot force_reset (主包 1.0 公共 API)
  - **不**实现: 业务规则, 持久化, 业务流

### 2.2 Owner

- Dashboard 拥有: routes, templates, static files, audit log
- 不拥有: 业务状态, 规则数据, metrics 数据

### 2.3 同步 / 异步

- 读: 同步 (HTTP GET → 读状态 → 返)
- 写: 同步 (HTTP POST → auth → 执行 → 审计 → 返)
- 实时: SSE (Server-Sent Events) 异步推送 metrics (每 5s)

### 2.4 现有抽象复用 (核对真实契约)

- `SentinelEngine` (M1.2): `state` / `in_flight` / `last_error` 公共属性
- `MetricRegistry` (M1.4): `snapshot()` 返回 `dict[resource_name, Snapshot]`
- `RuleRepository` (M1.5): `current()` 返回 `RuleSnapshot` 不可变规则快照
- `RuleSource` (M6.1.0b): `LegacyRuleSource.start/stop/latest` 触发 reload
- `DegradeSlot` (M2.x): `force_reset(rule_id)` 触发重置

### 2.5 模式评估 (per oop-design-guardrails §需求明确后)

评估 23 种 GoF 模式, 命中如下:

| 候选模式 | 位置 | 评估 | 决策 |
|---------|------|------|------|
| **Adapter** | HTML 模板 vs JSON API 双协议 | HTML 渲染 + JSON 响应是同一数据的 2 种视图 | **不**用 Adapter (避免双重实现, 用 Template Method / 函数路由) |
| **Template Method** | 路由处理: 读模板 / 读 JSON / 写 + 审计 | 处理流程相同, 区别在序列化层 | **不**严格用 (Starlette 路由天然分层, 不需要抽象) |
| **Strategy** | admin 鉴权: Bearer / OAuth / mTLS | 1.0 仅 Bearer | **不**用 (1.0 单一策略, 留 1.x 评估多策略) |
| **Facade** | `SentinelDashboard` 公共 API | 把 Engine / MetricRegistry / RuleRepository 聚合为单入口 | **用** (1 个 dashboard 对象 = 1 个 Facade) |
| **Observer** | 实时 metrics 推送 (SSE) | metrics 变化 → 推送 | **不**用 (pull 模式 SSE 足够, 5s 轮询简单) |
| **Decorator** | 路由中间件: auth / audit / rate limit | 中间件链 | **用** Starlette 中间件 |

**结论**: Facade + Decorator (Starlette Middleware) + 简单路由足够, 不引入额外模式.

### 3.2 公共 API (Facade)

```python
from atlas_richie.sentinel_dashboard import SentinelDashboard

dashboard = SentinelDashboard(
    engine=engine,
    metric_registry=metric_registry,
    rule_repository=rule_repo,
    rule_source=rule_source,        # optional, admin reload 用
    degrade_slot=degrade_slot,      # optional, admin reset 用
    host="127.0.0.1",
    port=8719,
    allow_admin=True,
    admin_token="secret",
)
dashboard.start()                  # uvicorn 在后台 task 启动
# 浏览器访问 http://127.0.0.1:8719/
dashboard.aclose()                 # graceful shutdown
```

### 3.3 跨语言 wire 协议 (M6.5) 集成

Dashboard **不**直接接收 M6.5 wire 协议 (那是 Collector Java/Go 的职责).
Dashboard 只读本进程 SentinelEngine 状态. 跨进程聚合留 1.x 候选.
