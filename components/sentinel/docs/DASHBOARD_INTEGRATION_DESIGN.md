## 1. 依据、产品决定与设计边界

### 1.1 已确认的产品决定

- 保留总览、应用与实例、规则、实时监控、故障分析、系统管理六个顶层导航；沿用已选的实例矩阵与旁侧诊断布局、深色皮肤、Astryx 控件、Nivo 图表。
- Java → Go → Rust → Python SDK 的应用接入顺序不变。Console/Collector 的 Python 实现可继续推进。
- 主机监控首期复用 Prometheus 兼容查询后端，提供主机/Kubernetes 采集部署引导；应用现有 Metrics V2 链路保留。
- 从配置中心读取到的规则立即可查看，无实例和零业务请求不妨碍读取；原生 JSON 和 Console managed 规则均展示实例加载观察。
- 配置中心保存线上规则；Console SQL 保存身份、登记/映射、受保护凭证、版本/审计等管理事实。外部监控后端持有主机时序。
- 固定 admin/view 两角色。admin 管理，view 按已有能力查看，无编辑。支持网页直接录入或部署引用凭证，不强制 KMS。
- 无观测时保留页面、显示局部提示与空图；0、无样本、未接入、未知和读取失败分别表达。

本文的布局、字段分组和交互细节是依据上述决定形成的可评审设计，不将尚未评审的 wire 路径、字段类型或依赖版本写成已冻结事实。

## 2. 功能全景、用户路径与页面职责

| 功能身份 | 用户痛点与来源 | 用户结果 | 主要入口 |
|---|---|---|---|
| UI-R01 规则目录 | 用户指出没有请求时看不到配置，不清楚是否已经读到 | 不发业务请求即查看已绑定配置中的规则和来源质量 | 规则 |
| UI-R02 当前规则与实例加载 | 用户要求知道有没有实例用、哪些在用 | 查看当前加载覆盖与具体实例，区分配置存在、加载、请求效果 | 规则详情、实例详情 |
| UI-S01 连接与采集工作区 | 用户指出主机监控无配置入口 | 区分并管理规则源、监控源与应用上报接入 | 系统管理→连接与采集 |
| UI-S02 监控源编辑 | 用户需要网页配置地址与认证 | 保存可重启恢复的监控查询源、映射与验证状态 | 监控数据源→新增/编辑 |
| UI-S03 采集与应用接入引导 | 填 Collector 地址不等于会有主机曲线，SDK 配置与监控采集不同 | 获取与部署方式匹配的可执行配置并验证实际接通 | 采集与上报接入 |
| UI-H01 主机目录与详情 | 主机没有业务实例时无处查看，多 worker 容易重复计算 | 独立查看主机压力、能力和关联实例 | 应用与实例→主机 |
| UI-M01 现有大盘接线 | 图表缺数据时整页失败、scope 混淆 | 同窗对比实有指标，缺失只影响对应面板 | 总览、实时监控 |

首次用户有两条独立路径：规则配置中心→关联已有配置→查看规则→应用接入→查看加载实例；监控查询源→采集部署/复用既有采集→核实主机→查看曲线。每条路径能独立推进，既不要求先有业务流量，也不把未接入监控当作规则功能失败。

熟练用户直接进入已登记 source/binding/host 的详情。首次提示最多四步，可关闭后从连接区重新打开，不改变服务器功能状态。

## 3. 全局交互与视觉约束

### 3.1 页面壳与任务上下文

沿用顶部水平六页导航、语言/会话控件与当前深色皮肤。标题下先放一句用途、当前范围/数据时间和局部状态，随后是筛选和工作区。不要复制一排与任务无关的 QPS 卡片到规则/系统页。

环境从后端登记的规则范围与监控范围联合目录读取，目录项带来源；规则页读取规则范围无需 metrics authority。只有监控源的环境也可在主机页使用。空目录提供登记入口，不能由 URL 或浏览器随意制造环境/应用选项。首次登记监控源可明确登记一个环境身份；首期一条监控源记录固定一个环境范围，同一后台可按不同范围另行登记。

导航保持环境、应用、时间及明确选择；频繁输入搜索采用 replace，显式打开详情采用 push。当前规则类型的 view 和系统 tab 的 view 继续按 feature 解读；新的选中规则、规则详情 tab、host/source/连接分区需扩展 typed route context，不能复用 view 同时表示两件事。查询参数精确名称属于路由增量设计，实体标识必须由当前授权目录验证。

### 3.2 密度、组件与布局

- 使用既有 4px 间距阶梯：控件间 8–16px、分区 24px、主要工作区 24–32px；正文沿用 14px/1.5，信息层级用标题/字重/间距，不靠超大输入框。
- 表单主内容最大宽约 760 CSS px；详情双栏仅在容器足够宽时展开。弹窗宽度受视口扣除两侧留白约束，最大高沿用 90dvh，只滚动 body，header/footer 固定。
- Astryx 输入/选择/复选/按钮只经现有共享封装使用；FormGrid 对齐 label、control、help/error 行，帮助文字置控件之后。同排长帮助行共同占位，不使用手写 margin-top 修某个输入框。
- 有编辑/多步骤/确认动作的浮层统一 DialogFrame；只读复杂详情采用页内旁栏，在窄屏转全宽详情，不叠加第二层编辑弹窗。
- 表格可见单元格用正式本地化名称，英文标识/checksum/配置路径作为辅助值显示，可复制；协议字段仅在明确标注的 JSON/高级信息中出现。
- 状态同时有文字/图标，蓝色=中性或进行中、绿=有证据的成功、黄=陈旧/部分、红=失败；未知不是红色告警，连接可达不代表业务健康。

## 4. UI-R01 规则目录与已有配置关联

### 4.1 桌面布局与信息层级

```text
规则                                      [关联配置 ▼]
直接查看配置中心规则；实例加载与请求效果单独确认。
[环境] [应用/全部] [规则类型/全部] [资源搜索] [刷新]
来源读取：3/4 个绑定已确认 · 最近读取 14:32   [查看未读绑定]
┌规则/资源────────类型──阈值摘要──配置来源──实例加载──操作┐
│POST /orders     流控  QPS 2000  Nacos A   已加载2/3  查看│
│GET /catalog     熔断  慢调用…   Consul B  覆盖未知    查看│
└────────────────────────────────────────────────────────┘
未读取的配置：Nacos C / flow-orders · 连接不可达 [重试此绑定]
```

“关联配置”是主要动作，菜单分“关联已有配置”“创建新的规则绑定”；已有独立新增规则入口继续在工作台，避免用户把创建绑定误当创建规则。view 可查看但不显示写动作。目录默认展示实际规则条目，不要求先点击某个绑定才能发现规则存在。

### 4.2 行、范围统计与刷新

| 内容 | 显示规则 | 用户操作 |
|---|---|---|
| 资源/规则名称 | 显示完整可辨识资源与类型；System 无 resource，显示“系统保护”；长值省略并可展开复制 | 查看精确 binding+快照中的规则 |
| 阈值摘要 | 由规则类型形成业务摘要与单位，不展示裸字段名；未知类型不擅自转换 | 查看全部条件与 JSON |
| 配置来源 | 来源名、Nacos/Consul、位置摘要，读取时刻；原生配置无 Console 版本时显示“外部配置” | 只读来源详情 |
| 实例加载 | 已确认 x/y、已确认 x 个/覆盖未知，或未知；陈旧单独标记 | 打开当前加载实例分栏 |
| 请求效果 | 仅在该 profile 可归因到此规则时显示同窗值；否则“未提供逐规则统计” | 查看实有指标 |

目录服务以有界的当前快照投影提供规则查询；原始规则权威仍是配置中心，SQL 索引/缓存只作为带 observedAt 的读投影。页面进入或刷新触发范围内有界更新，目录返回覆盖与逐绑定读取结果；后端限制并发/容量并隔离失败。刷新过程中保留同范围旧条目并标陈旧，不让浏览器无限逐绑定扇出。

managed 快照读取由绑定自己的严格 profile/target 读模型决定：原生数组沿用 profile adapter；对象形候选只有通过 Managed Publication V1 完整结构、精确 binding ID、rule kind、profile ID、payload checksum 校验后才能解包。未通过时整份候选失败并保留 last-known-good。`SENTINEL_CONSOLE_MANAGED_RULE_BINDING_IDS` 是 managed **写入/发布**授权名单，不是只读目录的解码名单；运行中登记新 binding 不需要重启或修改部署环境变量。此规则不扩大发布权限，也不扫描未登记的配置中心条目。

分页与资源搜索针对同一目录投影，必须回显查询、asOf、完整/部分覆盖及可确认的总数。部分绑定无法读取时，搜索无匹配只能显示“已读取范围无匹配”，不能宣称整个环境没有规则；未读绑定作为独立问题列表保留。尚不能确定的规则总数显示未知，不用当前页条数充当总数。具体页大小沿用现有分页能力，禁止另造无界列表。

新进入目录不自动发送业务探测请求。刷新、切筛选、重试此绑定均为只读操作；返回较旧请求时不可覆盖当前选择的结果。

### 4.3 关联已有配置交互

DialogFrame 分三步：①选择已登记规则源与明确环境/应用；②选择规则类型/profile 并填写 provider target；③读取预览并登记。Nacos 展示命名空间/分组/配置标识，Consul 展示数据中心/配置键，未选 provider 的字段不提交。

预览展示“读到 n 条规则”、配置版本/checksum/时间和有限只读条目。无配置项显示“配置项尚不存在，可登记后创建规则”，合法空数组显示“配置存在，尚无规则”；正文非法/不支持时提供明确的“登记关联，稍后修复”，登记成功后绑定仍标需修复，不能显示读取成功/可发布。该动作仍须通过既有绑定元数据、profile和target校验，仅保存关系、不改变正文；读取内容校验失败不能被当成元数据校验通过。

登记只写绑定管理关系，不改配置正文。提交结果未知时只核查原命令，不换 requestKey 重发；完成后定位新绑定并刷新目录。不在后台扫描接管全部 Nacos/Consul 配置。

## 5. UI-R02 当前规则详情与实例加载

### 5.1 布局与动作

宽屏规则列表与右侧只读详情并列；不足双栏宽度时打开全宽详情，返回保持筛选/页码/滚动。详情头展示规则业务名称、来源与当前快照时间，右侧唯一主要动作“编辑规则”（admin）；已有工作台承担编辑、校验、差异、版本与发布，不在只读旁栏再写第二套编辑器。

详情内部四分栏：配置详情、加载实例、请求效果、发布历史。默认配置详情，点击列表加载数字直接定位加载实例；页面不自动选第一条规则。快照已变更且规则无法再定位时显示“所选规则已变更/删除”，提供查看当前目录/保留的历史快照，不自动替换成另一条规则。

```text
POST /orders · 流量控制              [编辑规则]
来源 Nacos A · 外部配置 / 当前版本 · 读取 14:32
[配置详情] [加载实例] [请求效果] [发布历史]
当前加载 2/3 · 1 未确认 · 当前进程范围     [刷新状态]
实例         实际加载   当前配置匹配   最近心跳   详情
gateway-01   checksum A 已匹配          14:32     查看实例
gateway-02   checksum A 已匹配          14:32     查看实例
gateway-03   未观测     未确认          14:31     查看实例
```

配置详情保持来源目标、规则业务字段、当前源版本/checksum、只读规范 JSON。JSON 可复制，不能从查看动作写回。编辑时继承完整快照与版本基线；来源刷新检测到变化只提示差异，不能冲掉 dirty 草稿。

### 5.2 加载实例的精确含义

“使用实例”在本界面正式命名为“已加载实例”，表示当前认证进程加载的整组快照包含这条规则；不表示规则已被请求匹配或触发。加载成功必须来自 SDK/引擎实际 apply 后，拉取/解析成功不够。规则条目必须映射到精确快照成员；含数组位置的现有 record ID 不能作为跨版本稳定身份。

| 情况 | 可见文案 / 计数 | 不能推导的结论 |
|---|---|---|
| 完整登记目标目录为空 | “0 个已登记实例” | 实际部署环境永远不存在服务 |
| 完整三目标目录，无当前加载确认 | “已确认加载 0/3”，同时列 3 未确认/旧版/失败 | 未上报实例一定没有加载 |
| 完整三目标目录，两实例匹配 | “已确认加载 2/3”及第三实例实际状态 | 2 个实例一定产生了请求 |
| 两个可信加载观察，目标全集未知 | “已确认 2 个，覆盖未知” | 分母就是 2 |
| 缺观察/关联能力 | “使用情况未知”及接入原因 | 已加载数量为 0 |
| 进程换 epoch、撤销或 liveness 过期 | 从当前在线计数排除，历史另列 | 旧 applied 仍代表新进程 |
| 新候选加载失败、旧版仍运行 | 显示当前旧版与本次失败两项事实 | 当前实例没有任何保护规则 |

加载实例列表分页总数/计数由后端完整读模型给出，不能按当前页拼凑。提供“全部、匹配当前配置、其它版本、未确认、失败、离线/历史”筛选；缺能力的状态由显式 capability 表达，不把协议字段错误解析为未知。当前 liveness 使用服务端认证观察时间与明确新鲜度策略，浏览器在线不作依据。

旧 process epoch 不进入当前在线列表与当前规则使用计数。打开“历史进程观察”后，页面按精确 binding 读取当前 enrollment/epoch 之外的已持久观察事件，单独分页呈现 instance/process/epoch、事件类型、runtime checksum 和 Collector 收件时间；撤销、已被新 epoch 替代、当前 epoch 未知分别标注。无历史事件仅表示当前保留数据中没有历史观察，不等价于无实例或未加载。历史查询由登录读权限保护，不返回 principal、凭证或原始事件 body。

启动加载与成功热更立即上报；周期心跳独立于业务流量。原生配置按绑定/profile、进程身份及可比较的实际内容 checksum 关联；managed 继续保留 publication tuple。独立当前状态观察与 Runtime Receipt V1 的历史发布传播并存，不能伪造原生 publicationId。

### 5.3 请求效果与发布历史

请求效果显示窗口、scope、producer 与是否可逐规则归因。只有资源聚合 blocked 时可展示“资源保护统计”并标该资源可能有多条规则，不复制成每条规则的命中。无逐规则统计保持 unavailable，不为完成页面新造伪指标；0 仅在存在完整有效样本且确实为零时显示。

历史发布分栏复用既有 publication/receipt API，明确“发布历史”标题。没有 Console 发布历史的原生规则显示空历史，当前配置与加载分栏照常可用。同内容重复发布与回滚的新发布身份不能仅凭 checksum 判作同一次传播。

## 7. UI-S02 监控数据源编辑与检查

### 7.1 三步 DialogFrame

新增使用宽约 760px 的三步弹窗，编辑默认定位连接步骤但显示已有安全摘要。header 为标题/用途，body 是步骤内容，footer 为取消/上一步/下一步/测试/保存；只保留当前步骤主要动作。关闭 dirty 内容需要放弃确认；命令 pending 暂不能关闭，结果未知只核查。秘密不保存到浏览器草稿，刷新/关闭/撤权后清理。

| 步骤 | 内容 | 下一步与结果 |
|---|---|---|
| 1 连接与认证 | 来源名称、查询地址、认证方式、TLS；认证按选择渐进展示 | 本地结构校验通过进入步骤 2，不把此动作当网络验证 |
| 2 范围与身份 | 明确环境、受支持采集 profile、host identity 标签、有限筛选标签、采样周期/陈旧阈值 | 校验必需映射；可读的预览帮助用户核对范围 |
| 3 检查与保存 | 脱敏配置摘要、连接/权限/样本/身份/能力分别检查 | 检查成功可保存；无样本允许保存并给部署引导；未检查/失败可显式“仅保存为未验证”，不会显示健康 |

连接检查为只读，不登记/写 provider 配置；保存是独立命令。检查结果绑定当前候选与 source revision，任一相关字段改变就取消旧检查/清除成功标记，避免 A 地址的结果用于 B 地址。并发冲突保留非敏感输入，要求读取最新 revision 后重新确认；不得覆盖其它管理员修改。

### 7.2 字段行为

| 正式字段 | 必填/条件 | 交互与说明 |
|---|---|---|
| 来源名称 | 必填 | 用户识别名，不作为 provider/host ID |
| 监控查询地址 | 必填 | URL base，示例为 https://metrics.example.com；帮助写“用于读取指标和历史曲线”，不写 Collector |
| 认证方式 | 必选 | 无认证、直接录入、部署引用；没有默认猜测可用凭证 |
| 直接录入的认证类型 | direct 时 | 首期 Basic 用户名/密码或 Bearer token；字段只在适用模式出现，切模式清理旧秘密 |
| 保留现有凭证 | 编辑且已配置时 | 显示已配置状态，默认 keep；替换需输入完整新秘密，清除需选择无认证；不回显掩码字符串作真实值 |
| 部署凭证引用 | reference 时 | 后台可解析的标识；说明可以是部署 Secret/env 等提供，不要求 KMS |
| TLS 信任 | HTTPS 时 | 默认系统信任；可选部署提供的 CA/trust 引用。不以关闭证书校验作为普通表单选项 |
| 环境范围 | 必填 | 选择已登记环境，或明确登记新的监控环境身份；不根据地址自动推断 |
| 采集指标格式 | 必选 | 选择已实测 profile，例如 Node Exporter；OTel 导出转换 profile 只有验证后可启用，不按品牌假设指标名相同 |
| 主机身份标签 | 必填 | 指定 profile 认可的稳定标签组合；预览展示唯一/冲突/缺失，显示名称另设 |
| 查询筛选标签 | 可选 | 限定环境/job/cluster；键和值按受控参数处理，不输入任意 PromQL |
| 采样周期/陈旧阈值 | 必填或由 profile 确认 | 正式 API 增量定义范围；页面轮询周期不当采样周期，无证据不自动填已确认值 |

字段 label 在控件上，help/error 在控件后；两列共享 FormGrid 行结构。URL、身份映射和预览可占整行；不把超长说明插在同排某一控件之前。

### 7.3 检查结果与成功后的落点

结果面板逐项展示端点响应、查询权限、采集 profile、实际样本、标签唯一性和新鲜度。端点可达但 API 不兼容、能 query 但没有 host 指标、up=1 但没有 CPU/内存都分别说明。缺样本不是网络失败，映射冲突不能误显示主机数。

保存成功关闭弹窗，列表定位保存记录并读回服务器事实；提供“查看采集引导”和“查看已发现主机”。后者无样本时定位空目录并提示下一步，不导航到随机 demo。保存/检查期间 429 尊重后台等待提示，重复点击不增加并行请求；命令超时显示“结果待确认”，仅核查原操作。

## 8. UI-S03 采集部署与 Java/Go/Rust 应用接入

### 8.1 三条链路分别解释

| 接入卡片 | 地址/配置来自哪里 | 完成条件 |
|---|---|---|
| 规则加载 | 已登记 Nacos/Consul 与明确 binding/profile/target | Runtime 启动加载实际规则；配置读到和实际应用分别确认 |
| 应用状态/指标上报 | 部署提供的 Sentinel Collector 可达地址与认证 enrollment | 实际认证协商、规则状态或指标被接收；不要求先有业务请求 |
| 主机采集/查询 | 监控查询源 + 所选 exporter/OTel 部署配置 | 后端出现身份明确且新鲜的 HOST 样本；仅连 Collector 不够 |

运行时上报地址只读展示/复制，并注明“配置到应用端”；修改监听、Ingress、证书属于部署配置。页面可在缺地址时提示管理员设置部署项，不自行从浏览器 localhost 生成对外地址。主机 push 方案的 exporter 目标与应用 Sentinel Collector 是不同协议端点，按模板显示正式名称。

### 8.2 应用接入引导

四步：选环境/应用与语言→选规则绑定/支持 profile→取得与锁定 SDK/Adapter 版本匹配的依赖和配置示例→查看真实接入检查。Java/Go/Rust 仅在对应支持矩阵通过时可标可用；Python SDK 显示待接入，不输出伪可运行片段。

Java 优先采用用户真实 Gateway 的锁定依赖和官方 Sentinel 引擎；Go/Rust 使用官方 SDK 的已验证版本。配置片段区分原生 source 与 metadata-aware managed source；官方 SDK 不支持的协议通过明确 Adapter 提供，不能宣传只改 dashboard URL 就获得全部回执/指标。

接入检查包含“已登记目标、认证协商、配置拉取、规则已应用、状态最近上报”；每项由服务端事实推进，不能点“我已运行”就打勾。生成普通配置使用占位凭证或 Secret 引用，默认复制/下载不含真实秘密。

### 8.3 主机采集引导

提供“已有采集栈”“Linux 主机”“Kubernetes”三种部署路径。已有采集栈只校验 query/profile/labels，不要求重复安装；其它路径展示锁定版本、所需 mount/采集权限、环境/host labels、Prometheus scrape 或 OTel exporter 配置以及验证方式。

模板由服务端能力/profile 与所选范围生成，未解析的值以明确占位符显示并禁止标为可直接执行。UI 展示模板不等于远程执行部署；完成状态必须看到真实样本。Kubernetes host 与 container 所需组件分别列能力，不因选 Kubernetes 自动启用所有 scope。

初始化完成页/首次总览可显示“规则绑定、应用接入、主机采集”引导链接，但不重开一次性 setup，也不把监控当登录前置。

```text
│node-03 未关联应用     │ │CPU曲线       内存曲线        │
```

### 9.2 详情内容

头部：主机名称、稳定身份、来源、环境、可选 cluster/node 标识、读取/采样时刻及质量；不用综合“健康”绿灯代替单项能力。

摘要：HOST CPU 使用率（profile 明确容量分母）、内存已用/总量/比例、load；缺指标显示“未采集/无样本”。曲线分开 CPU、内存和 load 单位，同一 UTC 窗口。内存比例使用已确认主机总量，不能以容器限制替代。

关联实例区列应用、worker 实例、当前进程 epoch、关联证据来源/时间及最近上报；点击实例进入既有详情并保持可用上下文。一个主机承载多个 worker 只计一次主机压力。CONTAINER/PROCESS 导航只在具有对应身份及采集能力时启用，否则显示原因；HOST 数值不复制给其它层级。

来源已停用/删除、身份冲突、目标过期分别保留可解释状态。明确目标不存在时清理当前事实并要求重选；普通网络失败可以保留同身份同窗口旧值并标陈旧，不能换其它 host 数据。

## 10. UI-M01 总览、实时监控与故障分析的最小改造

总览保留现有大盘结构，新增“主机监控：已接入/待接入/部分覆盖”摘要和进入连接区动作；主机压力来自去重主机目录。应用 QPS/TPS/RT 和 Sentinel 阻断继续使用各自语义等价的来源，不随主机监控接通而自动推导。不同范围的比例不做无说明算术平均。

实时监控保留现有控制条、暂停/恢复和 Nivo 四/多图布局，增加明确的范围与主机选择入口；HOST 模式下主机目录不依赖 instanceId。范围切换使旧请求/选择失效，图表保留单位、来源、真实时间、新鲜度和空态。暂停仅暂停展示轮询，不停止采集；恢复沿用当前查询且不绕过 429 冷却。

故障分析只对已有权威事件/关联证据增加“查看主机”导航，身份明确才启用；主机曲线异常不自动生成事故或宣称根因。规则和系统页面不订阅主机曲线，也不因监控源失败而显示全页错误。

具体 HTTP 路径、严格字段与状态枚举必须进入主管 API/协议的版本化设计与机器 schema，再由前后端适配；本文不分配 /api/vNext 伪接口。所有 live/mock 页面共享相同 HTTP adapters，Mock 只在 HTTP 边界拦截，不能在组件里按 mode 生成成功结果。

### 11.3 关键时序

规则：Console 读取当前 source→独立展示；Runtime 启动从 source 拉取→校验→官方 SDK apply 成功→产生当前加载观察→认证 Collector 持久确认→当前覆盖查询更新；业务请求可始终为零。apply 失败上报候选失败并保留实际旧版，不上报假成功。managed publication 回执另经既有通路证明特定发布。

监控：admin 录入候选→只读检查→独立保存/revision→实际采集产生样本→Console 经 Prometheus Adapter 查询→身份/单位/窗口校验→返回局部质量与图表。Prometheus query_range 的包含终点必须转换到 Console [from,to)；求值时间不冒充原始样本新鲜度，缺测/非有限值不可绘制为零。

React 的 URL 只持非敏感选择；弹窗草稿/步骤是局部状态；source/host/rule/coverage 是独立 query resources；命令状态由 feature workflow 拥有。切范围/卸载取消请求/订阅/轮询；同查询只保留有界快照和同窗口旧事实，防止持续增长缓存。

## 12. 统一状态与恢复矩阵

| 场景 | 呈现 | 恢复/副作用 |
|---|---|---|
| 首次加载 | 保留标题/筛选/结构，局部 skeleton | 取消迟到响应，不能显示旧选择数据 |
| 刷新中 | 同身份旧数据带“刷新中/读取时间” | 独立资源刷新不遮住全页 |
| 没有规则绑定 | 规则页引导关联配置 | admin 可登记，view 看到需管理员配置 |
| 有效空规则数组 | “已读取，0 条规则” | admin 可去工作台新建 |
| 配置项不存在 | 显示目标不存在，与合法空数组区分 | 登记/创建明确动作不隐式写源 |
| source 非法/不支持 | 该绑定标不支持/需修复，保留其它规则 | 不丢字段后假成功，不渲染假阈值 |
| 无匹配搜索 | 说明已读取范围/是否完整 | 清空筛选，不把部分搜索当全量不存在 |
| 加载覆盖未知 | “使用情况未知”或“已确认x，覆盖未知” | 引导配置运行时状态上报，无伪0 |
| 无监控源 | 保留主机/图表布局与接入提示 | admin 跳监控源；规则功能可用 |
| 源可查询但无样本 | “连接成功，暂无指标”与空图 | 去采集引导/核查 profile |
| 映射冲突/缺失 | 列明确冲突/未关联，不混合主机 | admin 修改映射后重查 |
| 网络/503 | 局部失败，可信旧值标陈旧，否则空/不可用 | 有界重试同查询，不回退 Mock |
| 429 | 展示可重试状态，遵守 retryAfter | 不在冷却期间并发检查/刷新 |
| 401/撤权 | 会话/授权流程，清旧主体数据/秘密 | 无静默重放写操作 |
| 403 | 保留安全上下文，受限区域说明无权 | 不隐藏成无数据 |
| 版本冲突 | 保留非敏感输入，显示配置被修改 | 读最新后重做检查/确认，不能覆盖 |
| 命令 pending/未知 | busy/结果待确认与原命令核查入口 | 未确认前不换幂等键再提交 |
| 主机/进程 identity 退役 | 当前详情明确失效，旧事实不能冒充新目标 | 返回目录显式重选 |
| 停用/删除来源 | 局部来源不可用/不存在，审计保留 | 不把停用当零流量 |

### 13.1 响应式与键盘

| CSS 容器/视口 | 规则/主机工作区 | 系统管理与弹窗 |
|---|---|---|
| ≥1440px | 列表+旁侧详情，可保持矩阵与图表并列 | 紧凑表格、760px 编辑器，表单不随4K无限变宽 |
| 1024–1439px | 根据实际容器宽决定双栏；不足时全宽详情/返回列表 | 关键列保留，低频元数据进详情 |
| 768–1023px | 列表/详情切换，筛选可收起 | 表单空间够时两列，否则一列 |
| <768px，最小320px | 卡片列表，详情单列，图表纵排；上下文保持 | 全宽受限 DialogFrame，单列，footer可换行但按钮内文字/图标不拆行 |

触摸目标至少44px；操作支持键盘，不以整行 mouse click 代替明确按钮。DialogFrame 标题关联、焦点陷阱、Esc/关闭策略、关闭后回原触发点沿用共享组件；异步检查用适当 live region，持续刷新不抢焦点。表格有表头，图表有数字摘要/单位与质量说明，色彩不作唯一状态提示。200%缩放/长文案不能遮住页内动作；折叠/重排保留当前选择与非敏感草稿。动效遵循 reduced-motion。

### 13.3 页面与组件边界

现有 app 保持路由/服务组合；rules 拥有目录、当前使用读模型/mapper/workflow/只读详情；system 拥有监控源与接入引导；applications 拥有主机目录/详情；realtime/overview 组合各自观测。跨 feature 通过公共 Port/入口传参，不深导入另一 feature 私有文件。

共享层继续提供 DialogFrame、FormGrid、TextField/Select/ActionButton、局部状态和图表；当前规则覆盖卡、监控映射预览等先归业务 feature，不能仅因样式类似就提成万能框架。SCSS 跟随拥有组件的 module，皮肤值只由 core/styles token 提供；禁止恢复 legacy 样式或全局重写 Astryx内部 input/button。
